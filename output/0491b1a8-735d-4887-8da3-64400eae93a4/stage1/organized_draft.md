# 开发计划与任务清单

## 一、编制说明

本文件把已经确认的需求，翻译成可以开工的任务。依据三份材料：《需求重新梳理与现有方案符合性确认 V1.1》的十七条需求基线 R-01～R-17、《三维房间改造方案 V1.0》已经评审确认的 D1～D3 方向，以及对现有小程序代码与资产的核查结果。不写入未经确认的工期、人力与价格，也不承诺未经实测的性能数字。

一句话概括当前处境：核心功能和数据结构已经可用，真正挡在前面的是三维的观感与手感、数据换机、范围裁剪和上架准备；这些改造可以在现有代码上进行，不需要推倒重来。

## 二、计划总览

改造分七个阶段，按依赖关系排序。前一阶段的退出条件未通过，不进入下一阶段；每个阶段都能单独回退。第三、第五、第六章对应的工作互相独立，可并行推进，但验收仍按阶段分别进行。

| 阶段 | 名称 | 主要产出 | 对应需求 | 可并行 |
|---|---|---|---|---|
| 一 | 口径冻结与上架准备 | 品类清单、修订后的交互规范、备案与基础信息进度 | R-06、R-07、R-11、R-13 | 可与二并行 |
| 二 | 交互改造：恢复直接拖拽 | 新交互页面、数量角标、修订后的状态图 | R-05、R-17 | 可与一并行 |
| 三 | 美术资产重做：样板先行 | 样板家具、批量 GLB、真实缩略图、资产清单 | R-04、R-07 | 串行 |
| 四 | 户型与房间编辑 | 户型模板、改名改大小、增删房间、拖墙改形状 | R-03、R-06 | 串行 |
| 五 | 性能与真机基线 | 增量重建、拾取缓存、分级渲染、基线报告 | R-15 | 串行 |
| 六 | 数据导出导入与功能裁剪 | 导出导入页面、裁剪后的页面清单 | R-02、R-10、R-14、R-16 | 可与五并行 |
| 七 | 全量回归与提审 | 验收记录、提审材料与提交结果 | R-01、R-13 | 串行 |

## 三、阶段任务分解

### 阶段一　口径冻结与上架准备

目标：先把"做成什么样"定死，把不影响编码的合规事项同时启动，避免做到一半返工。

| 编号 | 任务 | 退出条件 |
|---|---|---|
| 1.1 | 冻结家具品类清单：柜、架、床、沙发、桌、椅、常见家电；明确绿植、地毯、灯具、摆件不做 | 清单评审通过并写入风格增补说明 |
| 1.2 | 修订 V1.3 交互规范与 V1.0 交互逻辑规范中被推翻的 A 方案条款、状态机与验收清单 | 规范与"直接拖拽"口径一致 |
| 1.3 | 填写小程序基础信息、提交备案；按个人主体、未认证的实际状态配置类目与隐私指引 | 备案受理或完成，基础信息填写完毕 |
| 1.4 | 备份当前可运行版本，建立回退点 | Git 提交或等价备份完成 |

说明：认证未认证不影响发布，只影响被搜索与被分享；但备案和基础信息是发布前必须完成的，这一步越早启动越好。

### 阶段二　交互改造：恢复直接拖拽

目标：先回收渲染器里已经写好的能力，让用户最快看到"能拖"这件事。这一步风险最低、见效最快。

| 编号 | 任务 | 退出条件 |
|---|---|---|
| 2.1 | 页面命中家具后不再锁死为点击，接回已有的拖拽预览接口 | 手指按住家具可拖动，抬手后位置保存 |
| 2.2 | 接入双指旋转与缩放；方向按钮降为精确微调备选 | 双指手势跟手，按钮仍可用 |
| 2.3 | 状态机由九态压缩为编辑态内子模式 | 浮层切换无冲突，撤销可用 |
| 2.4 | 网格吸附、越界钳制；相机视角变化不写为家具变更 | 家具不会拖出房间，转动视角不产生脏数据 |
| 2.5 | 新增家具数量角标：显示该家具下有效物品数，随移动与结束管理刷新 | 角标数字正确，不把物品画成三维模型 |
| 2.6 | BR-009 回归：换模型、拖位置、加品类均不破坏物品关联 | 关联关系零丢失 |

说明：本阶段不改美术资产；仍用现有白膜模型验证手感，避免视觉改动干扰交互判断。

### 阶段三　美术资产重做：样板先行

目标：把灰白素模换成彩色、造型可辨识的模型，并替换底部卡片的图标。这是观感提升最关键的一步，也是返工成本最高的一步，所以先做样板。

| 编号 | 任务 | 退出条件 |
|---|---|---|
| 3.1 | 选两到三件代表家具做样板，统一色板、大圆角、哑光材质、底面中心锚点 | 样板通过风格评审后再批量制作 |
| 3.2 | 按冻结清单批量建模，覆盖收纳家具与日常桌椅 | 每件可辨识、可点击、可绑定 |
| 3.3 | 离线渲染真实缩略图，替换底部卡片与家具卡片的占位图标 | 缩略图与模型对应，加载失败有降级 |
| 3.4 | 更新资产清单，复核主包与三维分包体积 | 均不超过 2 MB 上限 |
| 3.5 | 保留白膜与带色版备份目录 | 任一阶段可切回旧资产 |

说明：物品不在三维场景中显示，点家具弹面板看物品这条主路径不变。角标在阶段二已经做完，本阶段只保证数字与模型同步。

### 阶段四　户型与房间编辑

目标：让房间从"手填尺寸的固定盒子"变成"选模板就能用、还能随手改"的示意空间。不追求真实尺寸与测量精度。

| 编号 | 任务 | 退出条件 |
|---|---|---|
| 4.1 | 预置一室、两室、三室模板，房间名可改 | 选模板后可直接进入摆放 |
| 4.2 | 尺寸改为可选显示，不再作为必填项 | 不填尺寸也能建房 |
| 4.3 | 支持增删房间 | 新增或删除后家具归属正确 |
| 4.4 | 支持拖动墙面改形状，覆盖常见不规则形状 | 改形状后家具与物品关联不丢 |
| 4.5 | 复核模板、种子数据与既有家具的分类引用 | 无重复房间、无失效引用 |

说明：这一阶段可能牵动房间数据结构，必须在阶段二的 BR-009 回归通过之后进行。

### 阶段五　性能与真机基线

目标：解决拖动、缩放不跟手的问题，并在小米13上建立可对比的基线。不承诺未经实测的帧率数字。

| 编号 | 任务 | 退出条件 |
|---|---|---|
| 5.1 | 在改造前记录小米13上的进入页面、拖动、缩放耗时基线 | 基线数据留存，可与改造后对比 |
| 5.2 | 重建粒度下沉：只重建发生变化的家具实例 | 拖动时不再全场重建 |
| 5.3 | 拾取包围盒缓存，位置、角度、尺寸或相机变化时才重算 | 点击命中响应加快 |
| 5.4 | 按机型分级配置阴影、像素比与抗锯齿，提供低端降级 | 低端机不闪退、不明显卡顿 |
| 5.5 | 前后台切换暂停重绘、页面进入显示占位 | 无白屏、无无效重绘 |

### 阶段六　数据导出导入与功能裁剪

目标：解决换机丢数据，同时把范围收回到已经确认的核心＋历史＋库存。

| 编号 | 任务 | 退出条件 |
|---|---|---|
| 6.1 | 数据结构预留云同步扩展位，本期不接账号与云端 | 结构可扩展，当前无云依赖 |
| 6.2 | 打包导出为一个数据文件，支持微信传输 | 导出文件可正常发送到另一台设备 |
| 6.3 | 导入恢复，含版本号与异常提示 | 导入后物品、位置、历史、库存完整还原 |
| 6.4 | 用户说明写明：未导出就清缓存会丢数据 | 说明在设置页可见 |
| 6.5 | 直接删除照片、建模任务、备份降级页、后台页及入口，不保留隐藏代码 | 页面清单收敛，数据层不受影响 |

说明：旧版页面直接删除、不留隐藏代码已是你确认的决定；回退依赖版本管理，因此阶段一必须先建立回退点。

### 阶段七　全量回归与提审

目标：把前面所有阶段串起来验收，然后提交审核。

| 编号 | 任务 | 退出条件 |
|---|---|---|
| 7.1 | BR-009 全量回归、交互矩阵、静态门禁、运行时冒烟 | 用例全部通过 |
| 7.2 | 小米13真机验收，与阶段五基线对比 | 拖动缩放无明显退化，无白屏闪退 |
| 7.3 | 复核包体、备案状态、基础信息、类目与隐私指引 | 发布前置条件齐备 |
| 7.4 | 提交微信审核，按反馈修正 | 审核通过或问题清单闭环 |

## 四、验收口径

| 维度 | 通过标准 |
|---|---|
| 视觉 | 彩色可辨识、哑光低多边形、底部使用真实渲染缩略图，风格与样板一致 |
| 交互 | 选中即可拖动，双指缩放旋转跟手，吸附与钳制生效，按钮可精确微调 |
| 物品与数据 | 点家具弹面板看物品、数量角标正确；换模型、拖位置、加品类不破坏 BR-009 |
| 户型 | 三档模板可用，改名改大小、增删房间、拖墙改形状后归属关系正确 |
| 性能 | 小米13上建立改造前后可比基线，拖动缩放无明显卡顿，无白屏闪退 |
| 工程 | 每次改动均有 Git 提交，静态门禁、冒烟、交互矩阵、真机验收全部通过 |
| 包体与上架 | 主包与分包均不超过 2 MB；备案、基础信息、类目、隐私指引齐备 |

## 五、风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 口径反复 | 做到一半又改品类或交互方式 | 阶段一冻结清单与规范，后续变更走版本升级 |
| 包体超限 | 模型与贴图增加后超过 2 MB | 共享材质与图集、纹理压缩、按品类分批加载，每阶段复核 |
| 风格漂移 | 批量建模后与样板不一致 | 样板先评审通过再批量，统一锚点与色板 |
| 绑定关系被破坏 | 换模型或拖位置后物品丢失 | BR-009 作为阶段二、四、七的必过回归项 |
| 交互回归不彻底 | 旧 A 方案用例失效 | 同步修订规范与状态图，重建交互矩阵 |
| 真机性能退化 | 新资产在低端机卡顿 | 分级渲染与降级策略，必要时切静态预览 |
| 资产打包被过滤 | 真机上 GLB 被剔除只剩地板 | 保留 packOptions.include 与 ignoreUploadUnusedFiles 配置 |
| 上架条件不齐 | 备案或基础信息未完成导致无法提审 | 阶段一并行启动，阶段七复核 |

## 六、尚待你确认的事项

以下四项不写进任务清单的执行口径，需要你确认后再细化，本计划不代为决定。

| 事项 | 为什么需要你定 |
|---|---|
| 总工期与里程碑日期 | 决定并行程度与验收节奏，目前没有你给出的时间约束 |
| 谁来执行编码与建模 | 决定任务粒度是否需要拆到每日工作量 |
| 阶段顺序是否认可 | 当前按"先交互、后美术、再户型"编排，理由是拖拽风险最低、见效最快 |
| 是否先做一件样板家具给你看 | 样板确认后再批量，可以降低美术返工风险 |

## 七、结论

现有项目不需要推倒重来。七阶段中，阶段一、二是回收已有能力与改口径，风险最低；阶段三是观感提升的关键；阶段四、五、六分别补齐户型、性能与数据迁移；阶段七做整体收口。每个阶段都有明确退出条件和回退点，任一阶段未通过都不进入下一阶段。
