# 资料要点摘录

## 1. 小程序项目档案.md
- 项目名：三维室内空间与家庭物品管理小程序（居所收纳）；主体类型个人单用户。
- 数据形态：纯本地存储 `wx.Storage`，键 `home3d_store_v1`；云同步、云备份、云照片、云后台均已移出交付范围。
- 技术栈：微信原生小程序；Three.js r108 适配版 + 8 件白膜 GLB 置于 `package3d` 分包；Y-up、单位米。
- 页面：`app.json` 注册 21 页；`miniprogram/` 为唯一可交付产物，`demo/` 与 `prototype/` 冻结为只读参考。
- 归属模型：空间 → 家具 → 物品；物品必填 `spaceId`；`anchorType` 三态互斥；物品不持有坐标与 `roomId`。
- 当前阶段：B1–B5 已完成，B6 物理真机验收与 B7 提审准备待做；静态门禁、冒烟等全部通过。
- 真机待复验：资产打包过滤已修、V1.3 A 方案手势已改，仍需用户重新预览确认。

## 2. 产品总纲 V1.0（含 V1.2/CR-001）
- 定位：面向个人家庭用户的三维室内空间与家庭物品管理系统；用户手动创建/编辑三维场景，记录家具、收纳位置和物品，知道物品在哪里、曾经放在哪里。
- 核心场景：找物、归位、整理、补货、回溯。
- 产品原则：物品管理优先于三维视觉效果；渐进式建档；事实与预测分离；三维对象与逻辑位置解耦；失败可降级；用户确认优先；数据可追溯。
- MVP 必须实现：空间/房间管理、基础三维展示、手动添加家具与位置编辑、多级收纳节点、物品单件/连续添加、位置历史、易耗品库存与最低库存提醒等。

## 3. PRD 产品需求文档 V1.1
- 需求编号 PRD-001～034，覆盖账户与空间、照片与建模、三维与家具、收纳结构、物品档案、库存、后台/隐私/交付；PRD-034 位置推荐为 P1。
- 页面清单 UI-001～018；三维房间页为 UI-006。
- 关键规则：一个独立物品档案一个当前位置；首次设置位置不记为移动；移动与历史同事务；余额由交易记录支持；AI 候选不覆盖用户确认事实。
- TBD-001～008 已确认：首次位置确认、外出/借出、结束管理、同名节点、提醒周期、节点排序、计量单位、搜索筛选。

## 9. 本轮用户确认（问答记录，权威口径）
- 功能范围：核心＋位置历史＋易耗品库存；照片建模、云端后台等不做。
- 三维形态：示意即可、彩色、直接拖拽；不做真实尺寸建模。
- 位置颗粒度：房间＋家具＋抽屉（保留五层）。
- 使用与数据：要正式发布上架；换手机不丢数据改为"先做手动导出/导入，预留云同步"。
- 户型：预置一室/两室/三室模板；支持改名改大小、增删房间、拖墙改形状（常见不规则形状即可）。
- 物品呈现：维持现状，物品在列表，不进三维。
- 家具品类：收纳家具＋日常桌椅（柜/架/床/沙发/桌/椅/常见家电）；绿植、地毯、灯具、摆件不做。
- 风格规范：维持"收纳优先、剔除绿植地毯灯具"定位，不正式推翻。
- 改造方式：在现有代码上改，不重新做一套。
- 账号状态：用户已注册小程序，但主体类型与认证状态尚未确认。
