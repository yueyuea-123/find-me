# 居所收纳 · 三维室内空间与家庭物品管理小程序（MVP）

> **口径基线**：本文档以《当前基线（唯一口径）V1.1》为唯一依据。本文与基线冲突时，以基线为准；代码与本文不一致处，见 `document/文档-实现对账清单_V1.0.md` 与整改排期逐批收敛。

微信原生小程序，个人单用户**纯本地存储**版本。**开箱即用，断网可用，无需任何云端环境**。

## 一、快速开始

1. 打开微信开发者工具 → 导入项目 → 选择本目录 `iteam/`。
2. AppID 可选择「测试号」；如使用自有 AppID，请确保未强制开通云开发。
3. 编译运行。首次启动会自动填充一套演示数据（1 个空间 / 3 个房间「主卧·客厅·卫生间」/ 8 件家具 / 5 件物品）。首页户型总览按 demo 方案 A 视觉呈现。
4. 在「我的 → 清空数据」可重置为空库，从零体验完整建档流程。

> 本版本全部数据保存在微信本地缓存 `home3d_store_v1`，**不上传任何服务器，无云同步、无云备份**。清除小程序缓存会丢失数据。

## 二、功能地图

| 模块 | 页面 | 说明 |
|---|---|---|
| 空间 | `pages/space` | 空间新增/改名/归档/切换 |
| 房间 | `pages/room` | 房间新增/尺寸定标/建模任务状态入口 |
| 照片与建模 | `pages/photos`、`pages/task` | 照片增删；任务状态与失败后手动降级（本地版不虚报建模成功） |
| 三维 | `pages/room3d` | Three.js r108 分包渲染 + 8 件白膜家具；空白单指拖动转视角、双指缩放；选中家具后用「移动/旋转/尺寸」按钮或数值编辑，**禁止直接拖动家具**；编辑采用「编辑→完成→保存/撤销」草稿语义，保存前不落盘；加载或 WebGL 失败自动切列表 |
| 家具 | `pages/furniture-edit`、`pages/furniture-detail` | 家具增删改、外观与位置、换模型不动逻辑节点；删除家具时其下物品转入「未放置」兜底，不丢失 |
| 收纳节点 | `pages/node` | 多级收纳树、排序、关联物品 |
| 物品 | `pages/item-list`、`pages/item-edit`、`pages/item-detail` | 搜索筛选、单件/连续建档、完成度、结束与恢复；物品锚点三态：`furniture`（挂家具）/ `space_direct`（空间直挂）/ `unplaced`（未放置兜底） |
| 移动 | `pages/move`、`pages/history` | 首次确认/移出/归还/移动，全量历史可追溯 |
| 库存 | `pages/inventory`、`pages/inventory-detail` | 入库/消耗/调整、交易流水、库存不为负 |
| 提醒 | `pages/alerts` | 低库存提醒开启、忽略、达标自动恢复 |
| 我的 | `pages/profile` | 隐私说明、重置演示数据 |

## 三、技术约定

- **数据层**：`utils/store.js`，统一返回 `{ ok: true, data? }` / `{ ok: false, error }`。
- **归属模型**：空间 → 家具 → 物品。物品必填 `spaceId`；锚点 `anchorType` 三态互斥（`furniture` / `space_direct` / `unplaced`）；物品不持有坐标与 `roomId`，房间归属由所在家具推导。
- **三维保存语义**：编辑模式改动暂存草稿，「保存」时一次性提交到 store，「取消/返回」全量回滚；保存前 store 数据不变。
- **业务规则**：实现 BR-001~015 与 TBD-001~008，来源见产品文档目录的业务规则说明书与范围冻结清单。
- **三维**：Y-up、单位米；三维家具对象与逻辑收纳节点解耦；AI 候选与用户确认事实分离。
- **范围**：云同步、云备份、云照片、云端管理后台均不在交付范围（基线 §1、§6）。
