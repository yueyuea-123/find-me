## 1. 项目背景

家庭中常用小件物品（项链、耳机、卡片等）与易耗品（卫生纸、洗衣液等）分散存放在房间、家具、抽屉、收纳盒等多级位置，随时间推移容易遗忘存放位置或遗漏补货。用户需要一种低负担的方式，逐步建立家庭空间与物品的数字档案，可靠记录"物品现在在哪里、曾经放在哪里"，并管理基础库存。

产品方向由《产品总纲 V1.0》确立：以三维室内空间作为主要可视化入口，但物品与位置业务数据不依赖三维模型生成成功。需求经《PRD V1.1》《业务规则说明书 V1.1》《MVP 范围冻结清单 V1.1》逐轮确认，TBD-001～008 等 8 项核心业务规则已定稿并落入现有 P0 条目。

**V1.2 变更背景（CR-001）**：原方案以照片生成 AI 候选模型为主路径（photo_first），但通过普通照片直接建立可用的个人空间难度高、尺度不确定、建模质量与成本不可控。经决策改为提供一个**可自由编辑的三维场景**：用户手动创建房间布局、添加/移动/旋转/缩放三维模型，并将模型与物品及存放位置绑定。三维从"照片生成的产物"变为"用户直接编辑的画布"。此变更为主路径替换，已按一级变更批准。

## 2. 要解决的问题

| 痛点 | 具体表现 | 本文对应的解决方向 |
| --- | --- | --- |
| 找不到物品 | 忘记小件物品放在哪个房间、哪件家具、哪个收纳位置 | 建立"空间→房间→家具→收纳节点→物品"的可查找层级与搜索（MVP-019、MVP-014） |
| 位置不可信 | 物品位置随使用变动，记录与实际不一致 | 移动必须用户确认，当前位置与历史在同一事务内更新（MVP-023、MVP-024） |
| 建档负担重 | 一次性录入全家物品成本过高，用户放弃 | 渐进式建档：仅有名称也可建档，分类/照片/位置后续补充（MVP-022） |
| 易耗品断货 | 卫生纸、洗衣液等用完才发现 | 记录库存与阈值，达标时在小程序内提醒（MVP-027～030） |
| 建空间门槛高（CR-001） | 普通照片难以生成可用房间模型，用户卡在建空间第一步 | 手动编辑三维场景：直接建房间、摆模型、绑物品，不依赖照片（CR-001 F-01~F-03） |
| 三维不可用即不可用 | WebGL 或模型加载失败导致整个产品不可用 | 失败可降级：列表/手动通路始终可达（MVP-012） |
| 预测冒充事实 | AI 建议静默覆盖用户已确认的位置或库存 | V1.2 无 AI 生成环节，场景结构与绑定均为用户确认事实（MVP-011、业务规则 §10） |

## 3. 目标用户

- **唯一用户角色（首版）**：个人家庭用户，管理自己的一个或多个家庭空间。不支持家庭成员、共享空间与多人协作。
- **核心使用场景**：
  - 找物：通过房间—家具—抽屉/收纳盒路径定位物品，或直接搜索。
  - 归位：使用物品后记录新的存放位置，逐步形成可信档案。
  - 整理：建立房间与家具结构，查看多级收纳位置。
  - 补货：记录易耗品库存、消耗与最低阈值。
  - 回溯：查看物品位置变化历史，辅助判断可能所在位置。
- **运营侧角色**：基础管理后台仅用于排障与系统维护，默认不向运营人员开放家庭照片内容。

## 4. 核心目标

MVP 唯一核心目标：**让个人用户能够逐步建立家庭空间与物品数字档案，并可靠地记录物品当前位置、查找存放位置和管理基础易耗品库存。三维空间是主要可视化入口，但不是业务数据可用的前提。**

可验证的分项目标（PRD §3.1）：

1. 核心业务数据可独立于三维模型存在和使用。
2. 用户能创建多个空间、多个房间，并维护家具和多级收纳位置。
3. 用户能为独立物件建立档案，逐步完善信息并查询位置。
4. 移动事实和库存变化可追溯，数据前后一致。
5. 三维加载/编辑失败时，核心物品管理流程仍可完成。

## 6. 用户操作流程

### 6.1 主路径（happy path，PRD §8）

| 流程编号 | 流程名称 | 主路径步骤 |
| --- | --- | --- |
| UF-001 | 首次建立空间〔V1.2 重写〕 | 登录 → 创建空间命名 → 创建房间并手动填写宽/深/高（可默认）→ 选起点：空白房间或典型场景模板（预置一组家具，CR-001 F-07）→ 进入三维房间 → 从模型库添加家具或编辑模板预置家具 → 拖动/旋转/缩放调整 → 保存 |
| UF-002 | 建立家具与收纳〔V1.2 增强〕 | 进入房间编辑画布 → 从模型库选家具（或占位） → 拖动/旋转/缩放并保存 → 进入家具详情创建抽屉/隔层/收纳盒（收纳节点）→ 选中模型并将物品绑定到具体收纳节点 → 点选模型可查看关联物品 |
| UF-003 | 添加物品并完善 | 从首页/物品页或收纳节点添加 → 输入名称（分类/照片/备注可选） → 选跟踪模式与位置（可未知/外出/借出） → 保存单件或保存并继续 → 日后补完档案 |
| UF-004 | 移动物品 | 打开详情 → 选择移动 → 选目标位置或状态 → 确认 → 同事务更新当前位置并写历史 → 详情显示最新位置 |
| UF-005 | 库存管理 | 打开库存页或易耗品详情 → 选择入库/消耗/调整 → 填数量 → 校验并更新余额、记交易 → 达阈值显示提醒 |

### 6.2 异常与分支路径

- **模型编辑越界（CR-001）**：模型拖出房间或缩放超范围 → 钳制到边界与合理上下限并提示；不产生非法布局数据。
- **绑定冲突（CR-001）**：一个物品被绑定到多个模型 / 删除含绑定物品的模型 → 单物件单位置原则，只保留一个当前绑定；删除前阻断并提示先解绑或迁移。
- **三维不可用**：WebGL 不可用或模型加载失败 → 自动/手动切换到列表视图 → 房间、家具、收纳、物品管理仍可完成。
- **照片/建模任务（可选）**：若用户使用可选照片素材且处理失败 → 保留记录并可重试，不影响手动主路径。
- **首次位置**：unknown 状态首次确认到家庭内具体位置 → 记为独立"首次位置确认"事件，不伪装为 A→B 移动；创建时直接填初始位置不记移动。
- **外出/借出**：日常外出不强制记录；返回后可选具体位置或"在家，位置未知"，只记录用户明确执行的操作。
- **关联保护**：删除含物品的家具/节点 → 提示并先迁移或归档 → 处理完成后才允许删除/归档。
- **库存不足**：消耗导致余额低于零 → 拒绝并提示；纠错走"调整"交易，不伪装为消耗。

## 7. 输入和输出

| 流程 | 输入 | 输出 |
| --- | --- | --- |
| 建立空间 | 空间名称、房间基础信息 | 空间/房间档案；房间可停留在无模型状态 |
| 建立房间场景〔V1.2〕 | 手动录入宽/深/高（可默认）、起点选择（空白房间 / 典型场景模板）、可选照片素材 | 可编辑三维房间（layout 结构：墙面/地面/默认视角）；选模板时预置一组普通家具对象（可继续编辑）；不依赖照片，"估算"标注不再适用 |
| 家具/模型管理〔V1.2〕 | 模型库选择或占位、拖动/旋转/缩放、绑定物品与节点 | 家具场景对象（用户创建即确认事实）；模型—物品绑定关系 |
| 收纳结构 | 节点名称、父子关系、排序 | 多级逻辑位置树；与家具外观解耦 |
| 物品档案 | 名称（必填）、分类/照片/备注/跟踪模式/位置（可选） | 独立物品档案；当前位置（可未知/外出/借出） |
| 物品移动 | 目标位置或状态、用户确认动作 | 更新后的当前位置 + 一条位置历史（同事务） |
| 库存 | 入库/消耗/调整的数量与说明 | 更新后的余额 + 一条库存交易；阈值提醒状态 |

系统不采集与核心流程无关的家庭照片内容或敏感文本。

## 8. 异常场景

| 类别 | 场景 | 处理口径 |
| --- | --- | --- |
| 内容/数据 | 物品数据缺失、仅名称、位置未知 | 允许建档与保存，后续渐进完善；列表明确显示未知状态 |
| 数据 | 搜索无结果、空集合、空房间、空模型 | 显示空状态，不报错、不虚构位置 |
| 数据 | 库存余额将被扣为负 | 拒绝操作并提示，纠错走调整交易 |
| 数据 | 同名收纳节点、同级排序 | 允许同名，用完整路径与排序区分；排序只影响展示 |
| 交互 | 重复确认移动、连续快速添加、拖拽中断、重复保存 | 每项独立建档；动作幂等，避免重复记录；失败保留可恢复输入 |
| 交互 | 删除含物品的节点/家具/绑定模型 | 阻断并提示先解绑、迁移或归档 |
| 空间（CR-001） | 模型移出房间、缩放超上下限、角度越界 | 钳制到边界与合理范围并提示；统一 Y-up、单位米 |
| 模板（CR-001 F-07） | 典型场景模板缺失/加载失败、预置家具与房间尺寸不符 | 降级为空白房间并提示；预置家具按房间宽/深/高钳制；不虚构模板不存在的家具 |
| 绑定（CR-001） | 一物绑多模型、模型无绑定、换模型 | 单物件单位置；换模型保留节点与物品关联（解耦）；避免双绑定源 |
| 环境 | 三维/WebGL 不可用、模型加载失败、云不可用 | 自动/手动切列表，核心业务不中断；本地完整可用 + 待同步标记 |
| 边界 | 首次位置、外出后返回、库存为零 | 按 TBD-001/002/003 口径处理，不混淆事实类型 |
| 权限 | 非本人数据、非管理员访问后台 | 拒绝并返回明确提示；身份从服务端上下文获取 |

> 需求边界追问已按"内容/交互/数据/环境/边界"五类逐项检查，结论落入本节与 §10。

## 9. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 隐私 | 家庭照片与空间信息属敏感数据：私有存储、访问控制、安全传输；第三方 AI 用途须明确且未经授权不得用于训练；后台默认不开放照片内容 |
| 可靠性 | 模型编辑失败保留可恢复输入；WebGL 失败切列表；核心数据可独立于三维模型访问；离线优先，云端不可用时本地可用（CR-001：不再依赖照片/建模任务） |
| 数据一致性 | 位置更新与历史写入同一事务；库存余额由交易支持且不为负；绑定写入单源、换模型保留关联（V1.2 无 AI 候选，均为用户确认事实） |
| 可维护性 | 代码、数据结构、模型资源、部署配置与处理流程可交接；交付文档齐全 |
| 性能 | 三维加载、帧率、模型数量与低端设备兼容性须经真机验证后设定门槛，首版不虚构指标 |
| 成本 | 模型资源、存储与流量费用纳入预算与监控（V1.2 取消 AI 建模调用成本） |
| 供应商风险 | 模型库资源的授权与可替换性须明确；V1.2 主路径无第三方 AI 依赖 |
| 验收约束 | 每项 P0 需求对应测试用例、结果和问题记录；不以演示视频或静态效果图替代实际结果 |

## 10. 明确不做的事情

- **照片生成三维场景（V1.2 明确排除）**：不以照片作为建立空间的主路径；仅保留可选照片素材记录。
- **AI 自动重建/识别（V1.2 明确排除）**：不做照片→模型自动重建、不做家具自动识别、不做尺寸自动校准与自动摆放。
- 照片级真实三维渲染、专业 CAD/BIM 级测量精度。
- AI 全自动识别所有家具与小型物品且无需用户校正。
- AI 预测自动改变用户确认的位置或库存事实。
- 家庭多人实时协作、共享空间与成员权限。
- 复杂装修设计、家具购买与报价；自动采购或支付。
- 多人位置共享、跨用户公开物品或社区功能。
- 首版不承诺量化指标：房间重建准确率、家具识别准确率、尺寸误差、三维帧率、首次加载时长、单房间最大模型数、照片数量上限、AI 单次成本（MVP 冻结清单 §10、PRD §14.3）。
- 首版不建设复杂运营后台或完整运营分析系统。

## 11. 验收标准

### 11.1 MVP 核心闭环验收（PRD §14.1 + CR-001，逐条可验证）

| # | 操作步骤 | 预期结果 |
| --- | --- | --- |
| AC-01 | 登录并创建多个空间与房间，手动填写宽/深/高 | 创建成功，空白三维房间可打开，数据在列表中可见 |
| AC-02 | 在空白房间添加家具模型，拖动/旋转/缩放后保存，重新进入 | 模型存在，位置/角度/尺寸保持一致（CR-001 F-02） |
| AC-03 | 模型拖出房间边界 / 缩放超范围 | 自动钳制并提示，不产生非法布局（CR-001 空间边界） |
| AC-04 | 选中模型绑定物品与收纳位置；点选模型查看关联 | 绑定关系正确，可跳转物品详情；一物仅一当前绑定（CR-001 F-03） |
| AC-05 | 删除含绑定物品的模型 | 阻断并提示先解绑/迁移，物品与节点未被破坏（CR-001 关联边界） |
| AC-06 | 更换家具外观模型 | 逻辑节点与物品关联保持不变（MVP-016 解耦） |
| AC-07 | 在家具下建立多级收纳位置 | 父子层级正确，可从家具进入节点 |
| AC-08 | 添加一件物品，再连续添加多件独立物品 | 每件独立建档，位置关联正确 |
| AC-09 | 只填名称添加物品；之后补充档案 | 允许保存；后续可完善照片/分类/位置 |
| AC-10 | 搜索物品并查看最后确认位置 | 能搜到并看到位置；未知状态明确显示 |
| AC-11 | 确认一次物品移动 | 当前位置更新且历史同步增加一条 |
| AC-12 | 易耗品入库/消耗/调整；将库存调至阈值以下 | 余额正确、交易可追溯、不会低于零；小程序内可见提醒 |
| AC-13 | 模拟 WebGL/模型加载失败 | 自动切列表，家具/位置/物品管理仍可完成（CR-001 F-06） |
| AC-14 | 检查数据隔离、照片私有存储、备份恢复 | 通过检查，越权访问被拒绝 |
| AC-15 | 核对交付代码、数据结构、部署说明、模型清单、测试记录 | 交付物齐全 |
| AC-16 | 创建房间时选典型场景模板（如客厅）→ 检查预置家具 → 编辑/替换/删除其中一件 → 重进 | 房间带一组可编辑家具；改动保存后重进一致；与手动添加家具表现相同（CR-001 F-07） |
| AC-17 | 模拟模板缺失/加载失败 | 降级为空白房间并提示；房间创建与手动添加不受影响（CR-001 F-07） |

> 验收口径补充：MVP-004〔可选〕、MVP-005〔调整〕、MVP-007〔可选〕为 V1.2 降级项，不作为验收阻断项；AC-01～AC-17 覆盖本版核心闭环。

### 11.2 跨模块验收闭环（MVP 冻结清单 §9）

### 11.3 交付门禁（项目既定口径）

- 静态质量门禁 ≥ 90/100 且 0 个 P0 阻断项。
- 运行时冒烟断言全过、页面零异常（当前实测 48/48 断言、21/21 页、107 次事件调用）。
- 云后端真实部署可用（13 集合 + 6 云函数 + 定时备份触发器）。
- 验收以可重复操作的实际结果为准，不以演示或静态图替代。
