## 一、通用阶段模型（每个模块都走这 6 步）

| 阶段 | 名称 | 核心动作 | 必看文档 | 准出条件 |
|---|---|---|---|---|
| S1 | 需求与边界确认 | 锁定需求编号、冻结边界、异常口径、依赖 | 〔总纲〕〔冻结〕〔规则〕〔PRD〕〔proposal〕〔确认单〕 | 需求编号可列表；边界与异常口径无歧义；假设已登记 |
| S2 | 方案与技术设计 | 定数据结构、状态流转、接口、降级方案 | 〔design〕〔数据契约〕〔CR-001〕〔参考库〕 | 每条需求在〔design〕有对应章节；数据结构与接口落表 |
| S3 | 界面与交互布局 | 定页面结构、元素、交互、异常态 | 〔界面〕〔layouts〕〔参考库〕 | 每个页面有布局图；异常态有对应描述 |
| S4 | 编码实现 | 数据层→工具层→页面→云函数，逐层可运行 | 〔design〕〔数据契约〕〔tasks〕〔参考库〕 | 页面四件套可运行；云函数部署 Active；规则集中不散落 |
| S5 | 联调测试与门禁 | 跑静态门禁 + 冒烟 + 追溯矩阵 + 针对性用例 | 〔tasks〕〔矩阵〕〔验收报告〕、`qa/` 脚本 | 静态 ≥90 且 0 P0；冒烟全过；矩阵每条 P0 有证据 |
| S6 | 验收与交付 | 真机 AC 逐条验证、合规配置、签字与提审 | 〔proposal〕§11〔验收单〕〔部署〕〔档案〕 | AC 全过；合规项配置完成；按阶段签字提交 |

> 阶段门禁纪律：上一阶段未准出不得进入下一阶段；真机验证通过前不得把 AC 标为通过（〔规则库〕）。
> 不涉及 UI 的模块（M8 数据层、M9 云函数）可跳过 S3；纯文档变更（如本次计划）止于本文，不触发 S4。

## 四、模块开发顺序与依赖

```
M8 数据层 ──▶ M9 云函数 ──▶ M1 账户
                              │
                              ▼
                          M2 空间房间 ──▶ M4 家具收纳
                                              │         │
                                              ▼         ▼
                                        M3 三维编辑   M5 物品档案
                                                          │      │
                                                          ▼      ▼
                                                    M6 移动历史  M7 库存提醒
                                                          └──────┬──────┘
                                                                 ▼
                                                        M10 系统与提审合规
```

排序理由：
1. **M8/M9 先行**：所有业务模块依赖本地数据层与云后端契约，先定结构与接口避免返工。
2. **M1→M2→M4**：身份→空间房间→家具收纳，是数据与页面的自然层级。
3. **M3 置于 M4 之后**：三维编辑绑定的是家具/节点，须先有家具与节点结构。
4. **M5→M6/M7**：移动与库存都挂在物品档案之上。
5. **M10 收口**：系统页与合规依赖全部业务模块就绪。
