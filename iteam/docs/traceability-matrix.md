# 可追溯矩阵（traceability-matrix）

> **口径基线**：本文档以《当前基线（唯一口径）V1.1》为唯一依据。本文与基线冲突时，以基线为准。
> 用途：连接需求 → 设计 → 任务 → 用例 → 验收的端到端追踪链。每行一个需求项，右列填对应产物编号；空白即缺口。返工时沿行定位"改哪里、影响谁、哪些验收项需重跑"。
> **关联基线版本**：V1.2（CR-001 已批准）+ 基线 V1.1（云移出范围、V1.3 三维交互、归属模型） **维护人**：AI 辅助 + 产品负责人复核 **最后更新**：2026-11-23（B1 文档对账）
> **状态口径**：
> - `已验收(基线)` = 代码已实现、静态 100/100 通过；冒烟基线早期为 48/48，2026-11-20 固化 CR-001 断言后为 56/56。
> - `已实现(代码层)` = 阶段 H 已落地并通过门禁+针对性验证，真机 AC 待验（当前 T7～T10 全部达成）。
> - `待实现` = V1.2 新增能力中代码仍有缺口者；截至 2026-11-19 已无此类（T7～T10 全部落地），仅真机 AC 待验。
> - `待重验` = 受 CR-001 影响、已有功能需回归复核（三维编辑/绑定一致性/照片任务用例）。
> - **云端相关项（MVP-031/032 云部分、PRD-001~004 云隔离）**：**【已移出范围】**，追踪状态标注为"移出"，不作为验收项。
> - 分支/提交编号：阶段 H 已按"治理文档 / 代码"两路提交——`14dd289`（docs 五件套+存量口径）、`70eef50`（T7~T10 代码+smoke 注释）；基线 tag `baseline/pre-sdd`。两路未再按单任务拆分，因 T7~T10 共用 `store.js`，文件级不可干净分割（偏离 SDD §9 之处已记录）。
