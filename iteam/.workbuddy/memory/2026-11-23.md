## 真机反馈三处修正（同日下午）
- 用户反馈：①点家具后只能改家具、想调视图不便；②要在三维视图内出旋转按钮；③去掉下方红框按钮组（浏览模式"移动模型/↶90°/90°↷"）；④编辑器拖空白平移方向完全相反（手往右视图往左、手往上视图往下）。经确认"旋转按钮"指**旋转家具**（非旋转视角）。
- **pan 方向根因与修复**（`package3d/renderer.js`）：原 `pan` 用 `right=相机位置−target` 的右向/前向并取 −dx/−dy，轴向用反。提取共用 `screenDelta(dxPx,dyPx)`（A=水平位移 wpp、B=纵向 wpp/sin(pitch)，与 dragDelta 同口径），`pan` 直接对 target 减去 `(A·sy+B·cy, B·sy−A·cy)`，使内容跟手；`dragDelta` 也改用该函数，数值不变。经数值验证 yaw=π/4 时手往右 dx=50→世界(0.45,−0.45) 与屏幕右向同向。
- **视图内旋转按钮**（`room3d.wxml/.wxss`）：在 `.view3d` 内 canvas 之后加 `.view3d-rot`（右上，避开左上 `.view3d-badge`），两个圆形 `.rot-btn`（↶ data-dir=−1 / ↷ data-dir=1）均 `bindtap="rotateFurniture"`，`wx:if="{{selected}}"` 选中即显示；复用已存在的 `rotateFurniture`（每次±90°落盘），无需改 JS 逻辑。按钮为 canvas 兄弟节点、独立 bindtap，不干扰画布 catchtouch 手势。
- **去掉下方按钮组**：删除浏览模式"移动模型/↶90°/90°↷"与编辑模式下方旋转按钮，仅保留"编辑资料/添加物品/删除家具"。注意 `drag-mode-test.js:146` 断言 `data-dir="-1" bindtap="rotateFurniture"` 存在于 wxml——新视图内按钮保留了同样写法故断言仍命中（全库仅此 1 处）。隐藏兼容串 display:none 保留未动。
