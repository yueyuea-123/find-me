## 一、设计目标与原则

原型服务于三个目标：低门槛建档（名称即可建档，其余渐进补充）、位置可信（当前事实与候选建议视觉严格区分）、失败可用（三维、云同步任一失败时列表与手动通路始终可达）。

界面与原型须遵守六项原则：事实与预测分离；用户确认优先；失败可降级；解耦可见（家具外观与收纳节点分区展示）；数据可追溯（固定移动历史入口）；单手可达（高频操作集中于底部或拇指可及区，危险操作二次确认）。

> 说明：V1.2 已取消 AI 生成环节，场景结构与绑定均为用户确认事实；「候选/建议」样式规则予以保留，仅用于兼容历史候选数据与后续可选素材处理，不作为主路径状态。

## 四、用户流程说明

### 4.1 主路径（happy path）

| 流程 | 名称 | 主路径步骤 | 起点→终点 |
| --- | --- | --- | --- |
| UF-001 | 首次建立空间（V1.2 重写） | 登录 → 创建空间命名 → 创建房间并手动填写宽/深/高（可默认）→ 选起点：空白房间或典型场景模板 → 进入三维房间 → 从模型库添加家具或编辑模板预置家具 → 拖动/旋转/缩放 → 保存 | UI-002 → UI-006 |

### 4.2 异常与分支路径

- 模型编辑越界：模型拖出房间或缩放超范围 → 钳制到边界与合理上下限并提示，不产生非法布局数据。
- 绑定冲突：一个物品被绑定到多个模型 / 删除含绑定物品的模型 → 单物件单位置，只保留一个当前绑定；删除前阻断并提示先解绑或迁移。
- 三维不可用：WebGL 不可用或模型加载失败 → 自动/手动切换到列表视图 → 房间、家具、收纳、物品管理仍可完成。
- 照片/建模任务（可选）：若用户使用可选照片素材且处理失败 → 保留记录并可重试，不影响手动主路径。
- 首次位置：unknown 状态首次确认到家庭内具体位置 → 记为独立「首次位置确认」事件，不伪装为 A→B 移动；创建时直接填初始位置不记移动。
- 外出/借出：日常外出不强制记录；返回后可选具体位置或「在家，位置未知」，只记录用户明确执行的操作。
- 关联保护：删除含物品的家具/节点 → 提示并先迁移或归档 → 处理完成后才允许删除/归档。
- 库存不足：消耗导致余额低于零 → 拒绝并提示；纠错走「调整」交易，不伪装为消耗。
- 模板缺失（CR-001 F-07）：典型场景模板缺失/加载失败 → 降级为空白房间并提示；预置家具按房间宽/深/高钳制。

### 4.3 关键状态串接

| 流程 | 界面状态串联 |
| --- | --- |
| 首次建立空间 | 登录 → 空间列表空态 → 新建空间 → 房间列表空态 → 新建房间（选空白/模板，可跳过照片）→ 三维/列表房间页 |
| 建立家具与收纳 | 三维房间页 → 家具编辑页（新建）→ 保存回三维 → 家具详情页空节点态 → 添加节点 → 节点页可定位物品 |
| 添加物品并完善 | 首页/节点页 → 物品添加页（仅名称即可）→ 保存单件或继续 → 物品详情页逐步补充分类/照片/位置 |

## 五、界面交互逻辑

### 5.1 信息架构与导航

底部导航固定 5 项（核心任务入口不可改变）：首页（UI-001）、空间（UI-002/003）、物品（UI-010）、库存（UI-015）、我的（UI-018）。层级树：首页 → 空间列表 → 房间列表 →〔房间照片 → 建模任务（可选）/ 三维房间 → 家具编辑 / 家具详情 → 收纳节点（可多级嵌套）〕；物品列表 → 物品添加/物品详情 → 移动物品/移动历史；库存总览 → 库存详情；我的 → 账户/隐私说明/备份恢复/管理后台（管理员可见）。

### 5.2 页面布局与组件使用

整体采用低饱和冷色、克制清晰的风格；rpx 布局，页面左右边距 32rpx、卡片间距 24rpx、卡片内边距 32rpx、列表项 18～24rpx、表单项 24rpx；卡片圆角 24rpx、按钮圆角 12rpx、标签/徽章 999rpx；点击热区 ≥88rpx×88rpx，危险按钮与普通按钮间隔 ≥16rpx。

组件规范：主按钮为主色实心白字、置灰态给出原因文案；次按钮白底主色描边、危险操作用危险色文字+描边；状态标签实线=已确认事实、虚线+浅底=候选/建议且必须带文字；进度/任务态固定排队→处理中→成功/失败四态，失败附「重试」与「手动降级」两个出口；空状态统一「图标+一句说明+一个主操作入口」三段式；表单标签在上输入在下、必填标注、错误就近显示；弹层确认采用「标题+具体后果说明+取消/确认」，删除/归档/结束管理等不可逆操作必用。

### 5.3 交互反馈

写操作须有 loading 与结果反馈；错误文案说明原因与下一步动作，不暴露技术错误码；状态一律「颜色+文字+形状」三重表达，候选/建议带文字角标，避免色觉障碍误判；字体跟随系统设置，标题与正文比例稳定；所有可点元素须有明确反馈，跳转须有落点。

### 5.5 权限与数据限制

- 身份隔离：个人账户单用户；openid 从云函数上下文获取，前端不传；所有查询强制带 openid 条件，非本人数据拒绝并明确提示。
- 角色：管理员由 `users.role` 与环境变量 `ADMIN_OPENIDS` 判定；管理后台入口仅管理员可见，非管理员访问被拒。
- 数据保护：删除含物品的节点/家具/绑定模型前阻断并提示先解绑、迁移或归档；绑定写入与历史同事务；单物件单位置；库存余额不得为负。
- 隐私：家庭照片私有路径存储、短时授权链接读取；后台只显示任务状态与元信息，不返回照片内容；错误上报脱敏，不发照片与物品明细；第三方 AI 未经授权不得用于训练（V1.2 主路径无第三方 AI 依赖）。
- 离线限制：本地 wx.Storage 为主数据源；云端不可用时本地完整可用并标记「待同步」，恢复后重试；不显示虚假成功。
- 原型数据限制：原型为演示用途，mock 数据即可，不接真实后端、不处理真实鉴权与支付；不得在原型中写入任何真实家庭数据。

### 5.6 响应式要求

小程序端使用 rpx 覆盖 iPhone SE（375px）至主流大屏，三维画布按容器自适应、避免固定像素，底部操作栏适配 home indicator，弹层不遮挡关键操作。若原型以 HTML 线稿形式交付评审，须同时适配桌面（1440）/平板（768）/移动（375）三档视口，采用容器查询相对舞台而非浏览器宽度，保证视口切换条生效；断点以 768px 为界，桌面多列、移动单列。

## 七、原型设计要求

### 7.1 交付形态与范围

- 产出单文件目录（index.html + lofi.css + lofi.js），可直接双击打开，无 CDN 依赖。

- 桌面/平板/移动三档视口自适应；点击节点可跳转，主流程可从总览一路点通。

### 7.2 视觉规范（低保真线稿）

- 配色：仅灰阶+白+唯一红色 `#d93025`。灰阶层级 `#111` 标题 / `#3d3d3d` 正文 / `#767676` 辅助 / `#bfbfbf` 禁用；填充 `#f4f4f4` hover / `#ededed` 选中 / `#e2e2e2` 禁用 / `#2b2b2b` 主操作。
- 红色仅用于：必填与校验错误、危险/破坏性操作、错误 Alert/Toast、异常标签、待确认批注、热区标注；其余任何色相禁止。
- 控件高度 28/32/40（移动触控档 32/40/44）；圆角 2（按钮/输入/标签）/3（卡片）/4（弹窗）/全圆；间距 4pt 基准栅格，卡片内边距 16、字段间距 16、标签与控件 6；栅格 12 栏槽宽 16，桌面 4 列/平板 2 列/移动 1 列。
- 说明：产品视觉色板（主色 #2B7A9B 等）属于高保真设计规范，不在低保真线稿阶段使用；线稿以灰阶保证评审聚焦信息架构与任务流。

### 7.3 状态与交互规范

- 六态可演示：hover / focus / selected / disabled / loading / error；每页至少覆盖一种异常态（空状态/骨架加载/校验错误/禁用/无权限）。
- 交互全部采用声明式 `data-*` 驱动（跳转/弹窗/校验/加载），不写业务 JS；每个可点元素必须有行为，每个页面必须有编号与标题标识。
- 反馈时长：hover/focus ≤120ms，Toast 停留约 2.2s；破坏性操作（删除、归档、结束管理）二次确认。
- 待确认事项用红色批注标注在相关页面，交互规则用灰色批注写在页面底部。
