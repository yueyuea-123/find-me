## 1. 产品与范围

**产品定位**：家庭物品管理小程序。核心是物品的建档、查找、位置与库存管理；三维房间是物品数据的**呈现层**，不是第二核心。

| 项 | 结论 |
|---|---|
| 数据形态 | **纯本地存储**（`wx.Storage`）。云同步不在交付范围 |
| 移出范围 | 云同步（`cloud-sync`、`dataSync`、13 集合、6 云函数）、云端备份/恢复、云照片存储、管理后台云端统计 |
| 对应需求处置 | PRD-001~004、PRD-030、PRD-032 及 MVP-031/033 的云端部分不纳入本次验收；MVP 冻结清单 34 项 P0 以本表为前置裁剪，不再作为整体承诺 |
| 保留能力 | 本地建档、查找、移动历史、库存、提醒、本地备份导出/恢复、照片本地选图与展示 |
| 冲突裁定 | README「不上传服务器」与项目档案「13 集合同步」冲突，**以本地为准**；项目档案云端描述在对账批次收敛 |

## 2. 归属模型（已定稿）

**归属链：空间 → 家具 → 物品。物品跟随家具，家具跟随空间。家具锚点是可选的。**

### 2.1 物品模型口径

| 概念 | 口径 |
|---|---|
| 归属空间 `spaceId` | **必填，唯一归属空间** |
| 家具锚点 | **可选**。有锚点时经 `currentNodeId → nodes.furnitureId` 关联家具；无锚点即"空间直挂" |
| 锚点类型 `anchorType` | 三态互斥：`furniture`（挂家具）/ `space_direct`（用户主动空间直挂）/ `unplaced`（系统兜底未放置） |
| 三维坐标 | 物品**不持有任何坐标**；位置只由所挂家具决定 |
| 房间字段 | 物品**不持有 `roomId`**。挂家具物品的房间归属由家具所在房间推导；空间直挂与未放置不归属任何房间 |
| 历史 | 归属任何变化都写移动历史；`space_direct ↔ furniture` 互转记为一次 move，不伪装成位置未知 |

> 兼容说明：`space_direct` 与 `unplaced` 都只归属空间，但语义、入口和计数展示不同，不得合并实现。

### 2.2 三种锚点的行为

| 场景 | 规则 |
|---|---|
| 挂家具 | 正常态。物品位置 = 家具内收纳节点（节点只细化家具内位置，不改变归属） |
| **空间直挂（已确认允许）** | 用户主动选择"只归空间、不挂家具"。正常态，不需处理，不提示待办 |
| **未放置（兜底）** | 仅由家具被删除触发；系统兜底把物品放回该空间「未放置」区，**不删除、不静默丢失**，并提示用户重新指定家具或转为空间直挂 |
| 家具删除 | 其下物品 → `unplaced`，保留历史与物品本身 |
| 家具替换外观（换 model） | 归属不变，物品仍挂该家具 |
| 删除旧家具、以新家具替代 | 按"删除"处理：物品先进入 `unplaced`，由用户重新锚定，不自动挂到新家具 |

### 2.3 空间直挂物品在三维中的呈现

| 问题 | 口径 |
|---|---|
| 是否渲染 | **否**。三维场景只渲染家具；直挂物品没有家具锚点，**不得伪造坐标、不得挂到任意家具上展示** |
| 在哪里可见 | 在"空间物品"层级展示，带「空间直挂」标签；物品详情可查看归属空间 |
| 房间视图 | **不出现**在房间物品视图；房间计数不含它 |
| 如何进入三维 | 用户为它指定家具后，转为 `furniture` 锚定，才随家具出现在三维 |

### 2.4 计数口径

| 计数 | 口径 |
|---|---|
| 房间物品数 | 锚定家具属于该房间的物品数（`furniture` 且家具在该房间） |
| 空间物品数 | 该空间全部物品数 = 房间锚定 + 空间直挂 + 未放置，按 `item.id` **去重**，不得重复计入 |
| 首页/空间列表 | 用空间口径 |
| 三维房间徽标/抽屉 | 用房间口径，不含空间直挂与未放置 |
| 展示要求 | 空间口径下应能区分「空间直挂 N / 未放置 N」，便于用户处理兜底项 |

### 2.5 「未放置」与「空间直挂」的区别（不得混用）

| 维度 | 未放置 | 空间直挂 |
|---|---|---|
| 触发 | 系统兜底（家具被删除） | 用户主动选择 |
| 类型 | `unplaced` | `space_direct` |
| 是否正常态 | 异常态，需要处理 | 正常态，无需处理 |
| 是否有待办提示 | 有（指定家具或转为直挂） | 无 |
| 房间归属 | 无 | 无 |
| 空间计数 | 计入 | 计入 |
| 三维呈现 | 不渲染 | 不渲染 |

## 3. 验收口径（页面与视觉）

| 层 | 口径 |
|---|---|
| 页面总数 | 以 `app.json` 注册为准（当前 21 页）。**不得以"高保真只有 8 页"为由删减页面** |
| 视觉验收 | 交付稿 01–08 共 8 页按高保真 PNG/SVG 验收（结构、间距、层级） |
| 其余 13 页 | 只做**一致性验收**：设计令牌（`design-tokens.json` V1.1）、组件规范、空态/加载/错误态；**不做像素级比对**，**本轮不再重做视觉** |
| 全局换色 | 21 页统一到 V1.1 色板视为"设计令牌统一"，**不等同于** 21 页都做了高保真结构对齐 |
| 功能验收 | 21 页按《逐页交互说明书 V1.2》+ 本文件业务口径验收；云端页面按"本地降级态"验收或移出，不与云端联调 |

**收敛结论**：8 页对设计稿，13 页对规范；两者不互相否定，不再用"全量对齐"描述本轮工作。

## 4. 三维交互口径（2026-11-24 更新）

> **状态变更**：本节原以 V1.3 A 方案为准。用户在需求重新梳理阶段改选“直接拖拽”，现行基准改为 **《客厅三维空间交互与开发设计规范 V1.4》**；V1.3 A 方案降为历史参考。

| 项 | 结论 |
|---|---|
| 基准 | **《客厅三维空间交互与开发设计规范 V1.4》**（直接拖拽为主、按钮微调为辅） |
| 家具操作 | 单指拖动家具实时跟手、抬手落盘并按 5cm 吸附；双指旋转选中家具；方向/角度按钮保留为精确微调 |
| 相机 | 空白单指拖动转视角、双指张开/捏合缩放；相机变化不算家具数据变更 |
| 作废口径 | V1.3 A 方案的"禁止直接拖动家具、编辑—完成—保存草稿语义"**已作废**；V1.0/V1.1 及 README 中的"捏合缩放家具、双指扭转、长按删除"仍作废 |
| 保存语义 | 拖拽抬手/微调后改动即时落盘；“保存”按钮用于清空撤销栈与 dirty 确认，不改变已落盘事实 |
| 家具数量角标 | 三维家具顶部显示“内有 N 件”，0 件不显示；底部卡片同步 |
| 边界 | 三维只负责呈现与家具摆放；物品不与三维坐标绑定，点家具弹面板看物品；物品增删改查走物品页与物品规则 |

## 6. 明确不做（本期）

1. 不做云同步、云端账号/多端、云端备份与云照片存储。
2. 不做 AI 识别、照片生成三维模型、自动家具识别与自动摆放。
3. 不做"点物品反向定位到三维高亮"（本期）。
4. 不做多人协作、共享空间、角色权限。
5. 不做复杂运营后台、订阅消息、支付/采购。
6. 不做整体重写、换框架（Taro/uni-app）、重做数据模型。
7. ~~不做三维自由拖拽家具（与 V1.3 冲突）。~~ **已废止（2026-11-24）**：现按 V1.4 支持直接拖拽，见 §4。
8. 不做物品独立坐标、独立房间字段。
9. 不做空间直挂物品在三维中的虚拟/悬浮呈现。
10. 不做无设计依据的页面视觉重构。
11. 不为通过门禁修改测试断言；门禁分数不代表真机验收通过。
