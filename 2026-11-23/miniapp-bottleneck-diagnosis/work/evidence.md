## 4. 代码结构

- `room3d.js` 一个文件同时承担：GL 生命周期、分包加载、触摸拾取、相机、场景状态机、家具 CRUD、房间 CRUD、收纳节点查询、物品绑定、缩略图映射、待保存/撤销。属于 God Page。
- `store.js` 单文件承载空间/房间/照片/任务/家具/节点/物品/移动/库存/提醒/统计/同步适配全部逻辑；整库一个 JSON 存 `wx.Storage`，每次写全量落盘；无 schema 校验层。
- 物品与房间的归属关系不是显式字段：`items` 只有 `spaceId` + `currentNodeId`；`listItems({roomId})` 通过"节点属于该房间"反推，因此在外/借出或未绑定位置的物品不会出现在房间视图（2026-11-23 §八·补3/补4 记录了口径反复）。
- 死代码：`utils/webgl-renderer.js`(193) + `utils/room-renderer.js`(228) + `utils/mat4.js`(101) 无页面引用，仅互相引用。
- 冗余资产：`package3d/assets/furniture_colored_backup/` 228K 随包发布。
- 质量门禁性质：`qa/check_and_score.py` 是结构检查（配置/四件套/JSON 语法/路由/资源/字段存在性）；`smoke-test.js` mock 微信运行时调用页面方法，GL 用假渲染器验证异常降级。二者不能证明真机渲染、手势、性能正确。

## 4.1 三维展示层与物品域的耦合点（逐条可核）

| 耦合点 | 代码事实 | 含义 |
|---|---|---|
| 展示页直接做业务写 | `room3d.js` 55 处 `store.` 调用；移动/旋转/尺寸分别直接 `store.updateFurniture` | 三维页不是"呈现层"，而是第二个业务入口 |
| "待保存"是 UI 假象 | `moveStep`/`rotateStep`/`applyDimension` 每次点击即 `updateFurniture`（已落盘）；`saveScene` 只是重复写同值并清 dirty | V1.3 §7 的"先待保存、保存后提交"未在数据层成立 |
| 离开拦截不可靠 | 源码注释自认 `onUnload` 无法拦截系统返回；`onBack` 的"放弃修改"只回滚 `st[0]`（第一笔），多笔编辑时回滚不全 | 数据正确性依赖用户走的返回路径 |
| 房间物品口径靠位置反推 | `items` 无 `roomId`，`listItems({roomId})` 用节点反查；在外/借出/未绑定物品不出现在房间视图 | 物品归属语义是派生值，不是事实字段，随交互口径反复摇摆 |
| 渲染器依赖业务常量 | `package3d/renderer.js` 内 `require('../../utils/constants.js')`，按 `category`/`model` 映射 GLB | 分包渲染层反向依赖业务分类表，跨分包耦合 |
| 缩略图映射写在页面 | `room3d.js` 顶部用中文关键词正则匹配图片（沙发/电视/茶几…） | 展示细节混入页面逻辑，新增品类易漏（已出现"家具只有 3 种"类反馈） |
