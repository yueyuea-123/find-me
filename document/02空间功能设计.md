# Prompt：空间模块产品设计与开发规划

你现在担任本项目的产品经理、交互设计师和技术架构师。

请基于现有项目资料，为「家庭物品管理微信小程序」设计和完善【空间模块】。

## 一、项目背景

本项目是一款以三维家庭空间为核心的家庭物品管理微信小程序。

核心理念：

- 以房间为单位建立家庭空间。
- 通过三维模型展示房间及家具。
- 通过家具组织和定位家庭物品。
- 用户可以通过三维空间直观地找到物品存放位置。

开发模式：AI 主导开发，项目负责人负责确认和验收。

最终目标：交付真正可以上线使用的完整微信小程序。

设计原则：
1. 手机端优先，适配微信小程序。
2. 操作简单直观，降低用户学习成本。
3. 三维空间优先，物品管理辅助。
4. 不设计复杂的三维编辑操作。
5. 保持产品功能边界，避免无必要的功能扩张。

## 二、空间模块的核心组成

空间模块主要包含三个核心功能：

1. 建房间
2. 进入三维空间
3. 空间列表

空间首页负责展示家庭房间，并提供房间创建、房间切换和进入三维空间的入口。

## 三、房间模板体系

房间创建采用预设模板机制。

系统预设以下七种房间类型：

| 房间类型 | 默认家具模型 |
|---|---|
| 客厅 | 沙发、电视柜、茶几、边柜 |
| 卧室 | 床、衣柜、床头柜、梳妆台 |
| 厨房 | 橱柜、冰箱、餐桌、置物架 |
| 卫生间 | 洗手台、马桶、浴室柜、置物架 |
| 书房 | 书桌、办公椅、书柜、文件柜 |
| 阳台 | 洗衣机、收纳柜、置物架 |
| 其他 | 基础空房间，不预设家具 |

以上家具是模板的初始配置，具体模型和数量可以根据模板设计合理调整。

### 模板必须包含

1. 房间基础结构：地面、墙壁、门窗。
2. 家具三维模型。
3. 家具默认摆放位置。
4. 家具默认朝向。
5. 家具基础尺寸。
6. 房间与家具之间的空间关系。

### 模板管理原则

- 模板是系统预设数据。
- 用户创建房间时，系统根据房间类型复制对应模板。
- 创建后的家具布局属于用户自己的房间数据。
- 用户修改房间布局，不得影响系统原始模板。
- 用户可以删除、移动、旋转和增加家具。
- 用户删除模板家具后，不再显示该家具。

## 四、建房间交互流程

按照以下流程设计：

### 第一步：选择房间类型

展示七种房间类型。

每种类型需要有：
- 房间名称。
- 房间示意图或三维预览图。
- 默认家具说明。

用户选择一种房间类型。

### 第二步：填写房间名称

根据房间类型自动生成默认名称。

例如：
- 客厅：客厅
- 卧室：主卧
- 厨房：厨房
- 卫生间：卫生间
- 书房：书房
- 阳台：阳台
- 其他：我的空间

用户可以自由修改名称。

允许存在多个相同类型的房间，例如主卧、次卧、客卧。

### 第三步：创建房间

用户点击创建房间后：

1. 创建房间档案。
2. 记录房间类型和名称。
3. 根据房间类型加载对应三维房间模板。
4. 初始化模板家具及其布局。
5. 保存用户自己的房间数据。

### 第四步：自动进入三维空间

房间创建成功后，直接进入该房间的三维空间。

默认加载全部模板家具，不要求用户在创建前逐个勾选家具。

用户可以在三维空间中继续调整。

## 五、三维空间操作

三维空间是本产品的核心功能。

坚持简化操作原则。

需要支持：

| 操作 | 功能 |
|---|---|
| 查看房间 | 展示房间三维模型 |
| 选择家具 | 点击家具选中 |
| 查看家具 | 查看家具信息及关联物品 |
| 移动家具 | 调整家具位置 |
| 旋转家具 | 调整家具方向 |
| 删除家具 | 删除不需要的家具 |
| 添加家具 | 从家具模型库添加 |
| 绑定物品 | 将物品关联到家具 |
| 返回 | 返回空间首页 |

手机端交互要求：
- 单指拖动旋转三维视角。
- 双指缩放场景。
- 点击家具进行选择。
- 家具编辑操作通过简单工具栏完成。
- 避免复杂的三维操作面板。

注意：三维空间主要承担物品位置可视化和家具管理，不应演变为专业室内设计软件。

## 六、空间首页

空间首页需要展示：

1. 页面标题：我的空间。
2. 建房间入口。
3. 主空间展示区域。
4. 其他空间展示区域。
5. 查看全部空间入口。

建议采用：

- 主空间使用较大的展示卡片。
- 其他房间采用缩略卡片。
- 每个房间展示名称。
- 展示家具数量。
- 展示关联物品数量。
- 点击房间卡片进入对应三维空间。
- 支持快速创建新房间。

主空间应支持用户设置默认展示房间。

## 七、空间列表

提供独立的空间列表页面。

需要支持：

- 查看全部房间。
- 进入指定房间三维空间。
- 创建房间。
- 编辑房间名称。
- 修改房间类型（需要考虑模板与现有布局的兼容性）。
- 修改房间图片。
- 设置主空间。
- 调整房间顺序。
- 删除房间。

删除房间时必须考虑家具、物品与房间之间的数据关联，提供明确的二次确认和数据处理方案，不能出现无提示的数据丢失。

## 八、数据结构设计要求

请根据上述业务设计空间模块的数据结构。

至少考虑：

1. 房间数据。
2. 房间模板数据。
3. 家具模型数据。
4. 用户房间家具实例数据。
5. 家具与物品的关联关系。
6. 房间排序和主空间设置。

必须明确区分：
- 系统模板。
- 用户房间。
- 房间内家具实例。
- 家具关联物品。

确保用户修改自己的房间，不会影响其他房间和系统模板。
