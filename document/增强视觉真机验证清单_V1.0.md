# 增强视觉真机验证清单 V1.0

> **已废止（2026-11-22 方向变更）**：增强渲染器路线已放弃，视觉开关与 `room-renderer-enhanced.js` 均已从小程序移除。本清单不再执行；物理真机验收请按《Three.js资产化接入评估_V1.0.md》第六章进行。本文仅作历史留档。

> 目标：在微信开发者工具 + 真机上，对已完成的"视觉增强渲染器"做一次完整验收，判断是否可以设为默认视觉。
> 本清单**不改任何代码**。增强模式默认关闭、异常自动回退，验证失败可直接停在任何一步，不影响已验收的经典版本。
> 依据：视觉增强渲染器改造说明 V1.0、三维家具风格规范与预览验证方案 V1.0（§3 风格规范）。

---

## 一、验证前准备

| 项 | 要求 |
|---|---|
| 工具 | 微信开发者工具（最新稳定版） |
| 设备 | 至少 1 台 Android、1 台 iOS 真机；如条件有限，先用开发者工具模拟器过一遍 |
| 工程 | 用现有 `iteam/miniprogram` 工程，无需重新构建 |
| 数据 | 用 demo 默认数据即可（主卧、客厅、卫生间均已有家具） |
| 版本基线 | 当前为经典视觉默认、增强视觉可选；静态门禁 100/100、冒烟 75/75 已通过 |

**注意**：增强渲染器是原生 WebGL 单文件（约 19KB），不走分包、不依赖网络，真机离线可测。

---

## 二、进入验证场景

a) 打开微信开发者工具 → 导入项目 → 选择 `iteam/miniprogram` 目录，用测试号登录。

b) 编译后进入首页，点「房间 / 户型总览」，任选一个房间进入三维页面（room3d）。

c) 确认页面顶部模式栏最右侧有一个 **「经典视觉」** 按钮——这就是增强开关（当前显示"经典视觉"表示正处于经典模式；点它切到增强，按钮会变成"增强视觉"）。

d) 先停留在**经典视觉**，记住当前房间的观感，作为对照基准。

---

## 三、核心验证项（按顺序做）

### 项 1｜开关与回退

| 步骤 | 预期 |
|---|---|
| 点「经典视觉」按钮 | 按钮文字变为「增强视觉」，页面背景由深色切换为浅色（暖米白），画面重绘 |
| 再点一次切回「经典视觉」 | 按钮文字变回「经典视觉」，画面回到原渲染器观感 |
| 反复切换 3 次 | 无卡顿累积、无黑屏、无 WebGL 报错弹窗 |

若切换后弹出「增强视觉不可用，已用经典视图」——属自动回退，记录机型和系统版本即可，此项判为不通过。

### 项 2｜造型（对齐规范 3.1）

在增强模式下逐一观察，重点看是否告别"单个方块"：

| 家具 | 应看到的造型 |
|---|---|
| 沙发 | 底座 + 靠背 + 双扶手 + 双坐垫 + 抱枕（多部件圆角组合） |
| 床 | 床架 + 床垫 + 床头板 + 双枕 + 床尾巾 |
| 床头柜 | 柜体 + 双抽屉面 + 4 个拉手 |
| 衣柜 | 柜体 + 双开门 + 双拉手 |
| 茶几 | 桌面 + 四腿 + 台面小摆件 |
| 餐桌 / 桌 | 桌面 + 四腿 + 台面摆件 |
| 椅子 / 软包椅 | 座面 + 靠背 + 四腿 |
| 书架 | 两侧板 + 顶底板 + 隔板 + 彩色书籍 |
| 电视柜 / 抽屉 / 收纳盒 / 台灯 / 窗帘 / 躺椅 | 各自有专门部件组合，不是纯方块（对照改造说明 §3） |

判定：随机点开不同房间，**不应出现任何一件"孤零零的圆角方块"**。若某类家具显示为方块，记下类别名（说明该类未命中 `partsOf` 规则）。

### 项 3｜配色（对齐规范 3.3）

- 地板：浅原木色，不应偏深褐或发白。
- 墙面 / 背景：暖米白，低饱和。
- 家具：奶油白 / 原木 / 鼠尾草绿 / 芥末黄 / 陶土粉，整体高明度、低对比。
- 选中家具时：高亮偏陶红，不应出现刺眼的纯红或纯蓝。

判定：与 `preview/index.html` 的 Three.js 预览观感**接近**即为通过。允许原生实现与引擎实现有轻微色差，但不接受整体色调明显偏冷或偏暗。

### 项 4｜光照与视角（对齐规范 3.4 / 3.5）

- 视角：等距俯视，约 45° 方位 / 30° 俯角，家具三面可见。
- 阴影：家具底部有接触阴影（渐变圆斑），不是硬边投影。
- 光照：柔和、无明显高光斑和硬黑面。

判定：画面整体接近参考图的"娃娃屋"感，无过曝、无死黑。

### 项 5｜交互不退化（关键，必须全过）

增强模式必须保持与经典模式一致的操作手感，逐项做：

| 操作 | 预期 |
|---|---|
| 在空白处拖动 | 旋转视角；松手后画面稳定 |
| 双指捏合 / 滚轮 | 缩放；有上下限，不会拉到看不见或穿进模型 |
| 点「复位视角」 | 回到初始 45°/30° 视角 |
| 点选一件家具 | 弹出选中卡片，显示名称、位置、旋转、尺寸，以及关联物品 |
| 「编辑」模式 → 拖动家具 | 家具跟随移动，越界自动钳制在房间内 |
| 「编辑」模式 → 移动/旋转/缩放按钮 | 对应家具发生变化，数值更新 |
| 「收纳」模式 → 收纳节点 | 能打开，物品绑定信息正常 |
| 切换「列表（降级）」再切回三维 | 数据不丢，增强视觉仍生效 |

BR-009 底线：**换模型、拖位置不得破坏收纳节点与物品关联**。验证时任选一件已绑定物品的家具（如主卧双人床），拖动后再看选中卡片的"关联收纳 N 处 · 物品 M 件"是否与拖动前一致。

### 项 6｜性能与稳定

- 连续切换视觉、旋转、缩放 2 分钟，无闪退、无白屏。
- 低端机上若出现卡顿，记录机型；增强模式支持随时切回经典，可接受"低端机默认经典"。
- 退出页面再进入，增强开关状态回到默认关闭（当前实现不持久化，属预期行为）。

## 四、结果判定

| 结论 | 条件 | 后续动作 |
|---|---|---|
| **通过** | 项 1~5 全过，项 6 无严重问题 | 把 `room3d.js` 中 `enhanced: false` 改为 `true`（设为默认），再走一轮回归 |
| **基本通过** | 项 1~5 全过，仅个别低端机卡顿 | 保持可选；对低端机保留经典默认，高端机设增强默认 |
| **不通过** | 任一核心交互退化、家具显示方块、配色/视角明显偏离规范 | 保持经典默认，记录问题清单，回到规范调整 |

**回退方式**：任何阶段想回退，只需在三维页点「增强视觉」切回「经典视觉」，或不做任何改动——当前代码默认就是经典视觉，已验收版本从未被改。
