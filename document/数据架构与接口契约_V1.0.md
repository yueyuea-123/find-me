# 三维室内空间与家庭物品管理小程序 · 数据架构与接口契约 V1.0

> 适用环境：CloudBase（NoSQL 模式，个人版，ap-shanghai；环境 ID 以 `miniprogram/envList.js` 实际配置为准，敏感值不写入文档）
> 上位依据：PRD V1.1（PRD-001~004、PRD-030~033）、业务规则说明书 V1.1、产品总纲 V1.0；**现行变更 CR-001 / V1.2（三维主路径改为手动自由编辑）**
> 设计目标：在满足 P0 数据隔离/备份/后台要求的前提下，**保持现有 21 个页面的同步调用方式不变**（口径修订 2026-11-19，原记 18 页为陈旧数据）
>
> **V1.2 同步说明（2026-11-20）**：按 CR-001 已批准变更补齐手动编辑相关字段与接口口径，与 `iteam/docs/design.md` §5/§6/§7 保持一致。本文件仍为数据契约单一事实源；版本标识暂保留 V1.0（基线文件名不变），字段口径以本说明与 design.md V1.2 为准。照片/建模相关字段降级为可选、非主路径。组件与基础库版本以官方当前稳定版为准，不在此写死。

## 一、架构决策（关键）

### 1.1 问题

现有 `utils/store.js` 是全同步 API（`getItem()` 直接返回对象），21 个页面全部依赖这一契约。若直接改为云端异步读写，需重写全部页面，风险与工作量都不可接受。

### 1.2 方案：离线优先 + 云端持久化

| 层次 | 职责 |
|---|---|
| 页面层 | 继续调用同步 `store.xxx()`，零改动 |
| 本地数据层 | `store.js` 保留全部同步 CRUD，作为主数据源与离线缓存；每次写操作后标记"待同步" |
| 同步层（新增） | `utils/cloud-sync.js`：启动时登录并从云端拉取；写操作后异步推送；失败保留本地并提示 |
| 云函数层 | 强制用 `cloud.getWXContext().OPENID` 作为隔离键，忽略客户端传入的 openid |
| 云数据库 | 每实体一集合，`openid` 顶层字段 + 安全规则双重隔离 |

### 1.3 一致性口径

- **本地立即生效**：所有写操作先落地本地，用户无等待。
- **后台异步同步**：同步层按队列推送；成功清除"待同步"标记；失败保留并允许重试。
- **冲突策略**：以 `updatedAt` 较新者为准（last-write-wins）；MVP 单用户跨设备场景，冲突概率低，且保留冲突日志供排查。
- **关键事务**：`moveItem`（位置+历史）与 `inventoryTx`（余额+交易）在本地已保证同一函数写入；云端推送时打包为一次 `dataSync.batch` 调用，保证同源。

## 二、云数据库集合设计

所有集合均含 `openid`（String，必填）、`createdAt`、`updatedAt`。业务 id 沿用本地生成的 `xxx_时间戳_随机` 字符串，写入 `_id` 之外的独立字段（如 `spaceId`），避免云本地 id 冲突。

> 实现口径（2026-11-23 修正）：客户端 `store.js` 所有记录的主键字段统一为 `id`；`dataSync.batch` 按 `{openid, id}` 查重执行 upsert / remove。下表列出的 `spaceId`、`roomId` 等为关联字段或历史冗余键，不再作为业务主键；旧文档仍按冗余键兼容命中。`pull` 按 `id` 去重并清理历史重复副本。

| 集合名 | 业务键 | 主要字段 | 索引建议 |
|---|---|---|---|
| `users` | `_id` | openid(唯一), role(user/admin), status(active/banned), lastLoginAt | `{openid:1}` 唯一 |
| `spaces` | spaceId | openid, name, archived | `{openid:1, updatedAt:-1}` |
| `rooms` | roomId | openid, spaceId, name, width, depth, height, calibrated, **layout{floor,walls,camera}、source(manual/template/legacy_photo)、templateKey**(CR-001 F-01/F-07), photos[], task{}, archived | `{openid:1, spaceId:1}` |
| `furniture` | furnitureId | openid, roomId, category, name, model, position{x,y,z}, rotation, size{w,h,d}, source(manual/confirmed/legacy_candidate), status, confidence, **template(模板来源标记)**；绑定主通道复用 `nodes.furnitureId` + `items.currentNodeId`，不新增 `bindings` 双绑定源 | `{openid:1, roomId:1}` |
| `nodes` | nodeId | openid, roomId, furnitureId, parentId, name, type, order | `{openid:1, roomId:1}`, `{openid:1, parentId:1}` |
| `items` | itemId | openid, spaceId, name, category, note, photoPath, trackingMode, currentNodeId, locationStatus, managementStatus, completed | `{openid:1, updatedAt:-1}`, `{openid:1, name:1}` |
| `movements` | movementId | openid, itemId, type, fromNodeId, fromStatus, toNodeId, toStatus, note | `{openid:1, itemId:1}` |
| `inventory` | inventoryId | openid, itemId, balance, unit, threshold | `{openid:1, itemId:1}` 唯一 |
| `transactions` | txId | openid, itemId, type, delta, balanceAfter, note | `{openid:1, itemId:1}` |
| `alerts` | alertId | openid, itemId, cycleId, status, ignoredAt, recoveredAt | `{openid:1, status:1}` |
| `backups` | backupId | openid, snapshot(全量 JSON), type(auto/manual), recordCount, note | `{openid:1, createdAt:-1}` |
| `sys_logs` | logId | openid, level(info/warn/error), message, context, source | `{openid:1, createdAt:-1}` |
| `tasks` | taskId | openid, roomId, status, error, startedAt, finishedAt | `{openid:1, roomId:1}` |

### 2.1 安全规则（所有业务集合）

```json
{
  "read": "auth.openid == doc.openid",
  "write": "auth.openid == doc.openid"
}
```

> 管理后台不通过前端直连数据库，只走云函数；云函数服务端用管理员权限查询，前端无数据库直写权限。**规则以微信官方最新文档为准。**

### 2.2 照片私有存储

- 云存储路径：`photos/{openid}/{roomId}/{photoId}.jpg`，路径含 openid 天然隔离。
- 前端用 `wx.cloud.uploadFile` 上传，云函数签发上传路径；读取用 `wx.cloud.getTempFileURL` 换取短时链接。
- 运营人员默认无法查看照片内容；后台只显示任务状态与文件元信息。

### 2.3 V1.2 手动编辑字段约定（CR-001，与 design.md §5/§7 一致）

| 主题 | 约定 |
|---|---|
| 房间布局 `rooms.layout` | JSON：`floor{w,d}`、`walls[]`、`camera{yaw,pitch,distance}`；新建房间按宽/深/高生成，历史房间读取时懒兜底（不改存储、不动同步契约） |
| 房间来源 `rooms.source` | `manual`（手动/空白）、`template`（典型场景模板）、`legacy_photo`（历史照片房间）；选模板时 `templateKey` 必填 |
| 典型场景模板 | 静态预置于 `utils/constants.js` 的 `ROOM_TEMPLATES`（卧室/客厅/卫生间），用户主动选择、非 AI 推荐；落库后为普通家具对象，可自由编辑，改动不回写模板；缺失/加载失败降级空白房间 |
| 家具变换 | `position/rotation/size`，统一 Y-up、单位米；`transformFurniture` 支持 move/rotate/scale，编辑期越界钳制（`clampCenter`）、角度归一化到 [0,2π)、尺寸限 [0.1,12] 米 |
| 模型—物品绑定 | 单源：`nodes.furnitureId` + `items.currentNodeId`；沿该家具的节点聚合物品，`furniture.bindings` 不作为第二绑定源；换外观模型不破坏节点与物品关联 |
| 兼容说明 | V1.2 主路径无 AI 生成；`legacy_candidate`/`ai_candidate` 状态仅兼容历史数据，候选不自动成为用户确认事实 |

## 三、云函数接口清单

统一请求 `{ action, data }`，统一响应 `{ ok: true, data }` / `{ ok: false, error, message }`。所有云函数从 `cloud.getWXContext()` 取 OPENID，忽略客户端传入身份。

### 3.1 `userLogin` — 登录与身份建立（PRD-001）

| action | 输入 | 输出 |
|---|---|---|
| `login` | {} | `{ openid, isNew, role, status }` |

首次登录在 `users` 建记录；已存在则更新 `lastLoginAt`。登录失败返回明确错误码，不抛异常到前端。

### 3.2 `dataSync` — 全量同步（核心）

| action | 输入 | 输出 |
|---|---|---|
| `pull` | `{ since }` | `{ snapshot: {spaces,rooms,...}, serverTime }` |
| `batch` | `{ ops: [{collection, op, id, data}] }` | `{ results: [...], serverTime }` |

- `pull` 一次拉回该 openid 全部实体（MVP 数据量小，单用户远低于 100 条/集合上限）。
- `batch` 按集合分组顺序执行，同一事务内完成；任一失败整批回滚，返回失败项。
- 每次写入记录 `sys_logs`（level=info，message=集合+操作类型），供后台排障。

### 3.3 `photoService` — 照片私有存储（PRD-031）

| action | 输入 | 输出 |
|---|---|---|
| `signUpload` | `{ roomId, ext }` | `{ cloudPath, fileId }` |
| `signRead` | `{ fileIds[] }` | `{ urls[] }`（短时链接） |
| `remove` | `{ fileIds[] }` | `{ removed }` |

### 3.4 `backupService` — 备份与恢复（PRD-032）

| action | 输入 | 输出 |
|---|---|---|
| `create` | `{ type: 'manual'|'auto', note }` | `{ backupId, recordCount, createdAt }` |
| `list` | `{ page, size }` | `{ total, list }` |
| `restore` | `{ backupId }` | `{ ok, recordCount, restoredAt }` |

- 恢复采用"先建新快照再覆盖"，保证可回滚；恢复过程记入 `sys_logs`。
- 建议备份频率：每日自动一次 + 关键操作前手动一次；保留策略与恢复步骤写入部署文档。

### 3.5 `adminService` — 基础管理后台（PRD-030）

| action | 输入 | 输出 | 权限 |
|---|---|---|---|
| `tasks` | `{ status?, page }` | 任务状态列表（不含照片内容） | admin |
| `logs` | `{ level?, page }` | 错误/警告日志 | admin |
| `users` | `{ page }` | 用户数、状态统计（不含隐私数据） | admin |

- 角色由 `users.role` 决定，管理员 openid 通过云函数环境变量配置（不硬编码）。
- 后台只提供排障所需最小能力，不建设复杂运营平台。

### 3.6 `reportError` — 前端错误上报

| action | 输入 | 输出 |
|---|---|---|
| `report` | `{ message, stack, page }` | `{ ok }` |

写入 `sys_logs`；家庭照片内容永不上报。

## 四、错误码

| 错误码 | 含义 |
|---|---|
| `NOT_LOGIN` | 未取得 openid |
| `PERMISSION_DENIED` | 角色或 openid 不匹配 |
| `INVALID_ACTION` | 不支持的 action |
| `INVALID_DATA` | 字段校验失败 |
| `SYNC_CONFLICT` | 版本冲突（保留两端，记日志） |
| `STORAGE_FAILED` | 云存储读写失败 |
| `BACKUP_NOT_FOUND` | 备份记录不存在 |
| `INTERNAL_ERROR` | 服务端异常（记录日志，前端提示友好文案） |
