# 核心业务流程图 V1.2

> 目的：对应《近期执行顺序》第三步——"重点梳理空间、房间、家具、收纳位置、物品之间的关系"。
> 依据：`数据架构与接口契约 V1.0` §2、`utils/store.js` 实际关联字段、交互规范 V1.1 §1 对象边界与 §5 跨页导航、`物品添加与管理业务规则 V1.0` BR-009（模型—物品解耦）。
> 口径说明：截图点名的"空间、房间、家具、收纳位置、物品"在本项目数据模型中对应 `spaces → rooms → furniture → nodes → items` 五层；交互规范 V1.1 的文字树把二者合并写作"家庭→空间(客厅)→家具…"，本图按数据模型准确拆为五层，二者指向同一事实。
> 配套矢量图：`核心业务流程图_实体关系.svg`、`核心业务流程图_主流程.svg`。

## 一、五层对象关系（文字版）

```text
空间 space（如：温馨的家 / 3室2厅）
└── 房间 room（如：客厅）          关联：room.spaceId → space.id
    ├── 家具 furniture（如：电视柜）关联：furniture.roomId → room.id
    │   └── 收纳位置 node（如：左侧抽屉 / 上层隔板）
    │       关联：node.furnitureId → furniture.id；node.parentId → node.id（可多级）
    │       └── 物品 item（如：马克杯）
    │           关联：item.currentNodeId → node.id；item.spaceId → space.id（冗余，随位置校准）
    └── （家具与物品不直连：沿 nodes.furnitureId + items.currentNodeId 单源聚合，BR-009）
```

### 关联字段与基数

| 上层 | 下层 | 关联字段 | 基数 | 说明 |
|---|---|---|---|---|
| 空间 space | 房间 room | `room.spaceId` | 1 : N | 一个空间含多个房间 |
| 房间 room | 家具 furniture | `furniture.roomId` | 1 : N | 一个房间放多件家具 |
| 家具 furniture | 收纳位置 node | `node.furnitureId` | 1 : N | 每件家具建一个 `type=家具` 的根节点，下挂抽屉/隔板等 |
| 收纳位置 node | 收纳位置 node | `node.parentId` | 1 : N | 支持多级收纳；根节点 parentId 为空 |
| 收纳位置 node | 物品 item | `item.currentNodeId` | 1 : N | 一个位置放多件物品；物品当前位置唯一 |
| 空间 space | 物品 item | `item.spaceId` | 1 : N | 冗余字段，建档/跨空间移动时按节点所属空间校准 |

### 关键业务规则（关系层）
1. 每个收纳位置必须属于一件家具（根节点继承家具 ID）（BR-009）。
2. 物品同一时刻只有一个当前存放位置 `currentNodeId`；多位置数量拆分为后续扩展，首版不支持（交互规范 V1.1 §4）。
3. 家具—物品**解耦**：换外观模型不破坏节点与物品关联；沿节点聚合物品，不维护第二绑定源。
4. 删除房间/家具前需处理其下家具、节点与物品（store.js `deleteRoom`/`deleteFurniture` 有级联与阻断）。
5. 删除含物品的收纳位置前先迁移/清空绑定物品（交互规范 V1.1 §4）。

## 二、核心业务流程图（文字版，配 SVG）

### 流程 A：添加家具（对应页面 03）
```text
客厅空间(02) → 点「添加家具」
  → 选择家具模型（上一件/下一件）
  → 设置尺寸（长/宽/高，cm）
  → 位置调整（移动 / 旋转 / 缩放，工具互斥）
  → 点「完成添加」
      ├─ 校验失败(尺寸无效) → 就地提示，返回修改
      ├─ 放弃(返回) → 二次确认「放弃修改/继续编辑」
      └─ 校验通过 → 保存家具(furniture.roomId=当前房间)
                   → 自动生成 type=家具 的收纳根节点(node.furnitureId)
                   → 返回客厅空间，新家具选中
```

### 流程 B：添加物品 / 建档（对应页面 05，三个入口）
```text
入口①首页「添加物品」  入口②三维点家具/收纳位置  入口③我的物品
  → 添加物品页(05)
  → 填名称 / 分类 / 数量
  → 选存放位置：空间→房间→家具→收纳位置（入口②已预选）
      └─ 不选 → 位置未知，后续移动页首次确认
  → 拍/选图片、填备注
  → 点「保存」
      ├─ 校验失败 → 就地提示
      └─ 通过 → 写 items：currentNodeId=所选节点, spaceId=按 spaceIdOfNode 校准
              → 返回来源页并刷新
```

### 流程 C：移动物品 / 位置历史（对应 pages/move、pages/history）
```text
物品详情(07) → 移动
  → 选状态：在家 / 带出 / 借出
      ├─ 在家 → 必选具体收纳位置（首次确认记 first_confirm）
      ├─ 带出/借出 → 保留常驻位置 homeNodeId，清空 currentNodeId
      └─ 归还 → 有有效常驻位置可自动回填(autoBack)
  → 确认 → 写 movements 历史(from→to + 状态 + 时间)
         → 更新 item.currentNodeId / locationStatus / spaceId
  → 位置历史页可全量追溯
```

### 流程 D：库存与提醒（对应页面 08、inventory-detail）
```text
库存管理(08) → 按全部/易耗品/长期用品筛选
  → 点库存卡 → 库存详情：入库(+)/消耗(-)/调整(设余额)
      → 写 transactions，更新 inventory.balance
      → 余额 < threshold 时卡片显示「低于 X 提醒」红色进度条
  → 结束管理物品前：须先将结存清零（业务规则），再走 disposal 留痕
  → 提醒不改变物品与收纳位置归属关系
```

## 三、可点击导航一致性（对应 §5 数据传递）

| 起点 | 操作 | 终点 | 沿关系链传递 |
|---|---|---|---|
| 首页 | 空间卡 | 房间入口 | spaceId |
| 客厅空间 | 点家具 | 电视柜管理 / 建档 | roomId + furnitureId（+ 预选 nodeId） |
| 电视柜管理 | 点收纳位置 | 位置物品列表 | furnitureId + nodeId |
| 我的物品 | 点物品 | 物品详情 | itemId |
| 物品详情 | 移动 | 移动页 | itemId + currentNodeId/homeNodeId |

> 具体字段上限、尺寸默认值、库存阈值等按业务规则说明书 V1.1 执行，本图不臆造数值。
