# 三维空间视图与模型管理交互设计规范 V1.0

-   **文档状态：** 设计基准建议稿
-   **版本：** V1.0
-   **适用项目：** 物品记录管理小程序
-   **建议存放路径：** `document/kywork/3d/`
-   **设计方向：** 固定等距轴测视角的轻量化三维房间场景

------------------------------------------------------------------------

## 1. 文档目的

本文档用于明确物品记录管理小程序第一版的三维空间视图、家具摆放及物品绑定交互方案，作为后续页面原型、数据结构和开发实现的共同依据。

本项目的三维能力不是专业三维建模工具，也不是完整的室内设计软件。三维场景的核心作用是：

1.  让用户直观了解家具在房间中的相对位置。
2.  让用户通过点击家具找到对应的存放位置。
3.  让用户将物品绑定到家具，并查看家具中存放的物品。
4.  用较低的操作成本建立可视化的物品存放关系。

**核心原则：三维视图服务于物品管理，而不是让用户为了使用物品管理功能而学习三维建模。**

## 2. 产品定位与设计决策

### 2.1 最终产品形态

采用"轻量三维家具管理视图"：

-   用户可以创建或进入一个房间。
-   房间以简化的三维场景呈现。
-   用户从家具库添加家具模型。
-   用户可以调整家具在房间中的位置和朝向。
-   用户点击家具，查看或管理绑定在该家具上的物品。

第一版不提供完整房屋设计、专业建模、复杂场景编辑能力。

### 2.2 视觉风格

采用用户提供的参考图所体现的**等距轴测房间视图（Isometric Room）**风格。

视觉特征：

-   固定的斜上方等距视角。
-   展示地板及两面墙，形成直观的房间剖开展示效果。
-   家具以独立的三维模型呈现。
-   整体偏简洁、柔和、轻量的卡通化或低多边形视觉风格。
-   家具、墙面和地板的视觉语言保持统一。
-   背景尽量干净，突出家具和物品存放位置。

### 2.3 视角策略

第一版采用固定等距视角，不允许用户自由旋转整个房间摄像机。

这样做是为了：

-   保持不同房间和家具视图的一致性。
-   降低移动端手势冲突和操作难度。
-   减少视角变化导致的选中、拖动和定位复杂度。
-   让用户把注意力集中在家具和物品上。

如后续测试证明用户确实需要更多观察角度，再评估是否增加有限的视角切换，而不是直接引入自由摄像机控制。

## 3. 页面与界面结构

### 3.1 页面原则

采用单一主视图，不采用专业三维编辑器式的多面板工作台。

建议页面组成：

1.  顶部：当前空间或房间名称，以及必要的基础操作。
2.  中部：主要三维房间视图。
3.  底部抽屉：当前选中家具的操作入口及物品管理入口，三维场景作为背景保持可见。抽屉展示家具摘要、收纳节点、各节点有效物品数与添加物品入口，支持收起/关闭（ITEM-DEC-002，详见《物品添加与管理业务规则 V1.0》§3.2）。

家具库可通过"添加家具"入口打开为抽屉、弹层或独立选择页，不必常驻占据屏幕。

### 3.2 三维视图

三维房间视图是页面的主要区域，应优先保证：

-   房间整体轮廓清晰。
-   家具之间的相对位置容易辨认。
-   家具可被点击选中。
-   选中状态有明确视觉反馈。
-   家具较多时仍可进行基本浏览和选择。

### 3.3 家具选中状态

点击家具后，底部抽屉应至少提供：

-   家具名称与有效物品总数。
-   收纳节点列表及每个节点的有效物品数量；点节点切换为该节点的物品列表。
-   查看全部物品入口。
-   添加物品入口（默认继承当前家具/节点）。
-   必要的家具编辑入口（折叠在「更多」中）。

选中状态可通过描边、底座高亮、轻微强调或其他统一视觉方式表现。不要同时叠加过多控制按钮，以免遮挡家具。

## 4. 家具管理与交互规范

### 4.1 添加家具

基本流程：

1.  用户点击"添加家具"。
2.  打开家具选择界面。
3.  用户浏览或搜索家具类别。
4.  选择家具模型。
5.  家具出现在房间场景中的默认位置。
6.  用户确认或调整位置。

家具库第一版建议提供常见家具类别，例如：

-   衣柜
-   书架
-   桌子
-   床
-   沙发
-   电视柜
-   收纳柜
-   冰箱
-   鞋柜
-   其他收纳家具

类别可根据实际模型资源逐步扩充，不要求第一版覆盖所有家具类型。

### 4.2 家具摆放

第一版支持：

-   拖动家具调整平面位置。
-   通过简单操作调整家具朝向。
-   必要时提供有限的尺寸规格选择。

第一版不要求用户输入专业 XYZ 坐标，也不要求提供专业三维变换控制器。

交互应适配手机触屏，避免依赖键盘快捷键或精细鼠标操作。

### 4.3 家具旋转

家具旋转用于调整家具在房间中的朝向。

建议采用简单、可预测的旋转方式，例如按固定角度步进旋转。具体角度步进可在原型测试后确定。

### 4.4 家具尺寸

第一版优先使用家具模型预设尺寸或规格选项。

如果某类家具确实需要用户调整尺寸，再提供简单的尺寸设置入口。暂不提供复杂的自由缩放、轴向缩放和专业尺寸编辑。

### 4.5 删除家具

删除家具时应区分"删除场景中的家具对象"和"删除物品记录"：

-   删除家具不应自动删除其绑定的物品记录。
-   删除前应提示用户处理家具下已有的物品归属。
-   可在后续产品规则中确定：将物品移动到未分配位置、重新选择存放位置，或暂时保留原存放关系并提示异常。

**禁止因删除家具模型而静默丢失物品记录。**

## 5. 家具与物品绑定

### 5.1 核心关系

第一版采用"家具作为物品存放位置入口"的方式。

示例：

``` text
房间
├── 衣柜
│   ├── 物品 A
│   ├── 物品 B
│   └── 物品 C
├── 书架
│   ├── 物品 D
│   └── 物品 E
└── 书桌
    └── 物品 F
```

家具是三维场景中的可视化对象，物品是业务数据。物品不需要因为被绑定到家具，就必须拥有独立三维模型。

### 5.2 绑定流程

1.  用户点击三维场景中的家具。
2.  系统选中家具并打开底部抽屉，显示家具名称、有效物品总数、收纳节点及各节点物品数。
3.  用户可选择具体收纳节点，查看该节点直接关联的物品；也可直接选择"添加物品"。
4.  新建物品时表单预选当前家具/节点；从已有物品中选择时写入当前节点存放关系。
5.  保存后家具与节点计数、物品列表同步更新。

### 5.3 查看物品

点击家具后，用户可在底部抽屉中查看当前节点物品，或进入该家具的完整物品列表。

物品列表至少应支持：

-   查看物品名称和缩略图（如有）。
-   查看基本物品信息。
-   进入物品详情。
-   添加物品。
-   修改物品的存放位置。

### 5.4 家具内部结构

第一版不要求家具具有真实的三维内部结构，也不要求实现抽屉、隔层的真实开合动画。

如果业务确实需要更细的存放位置，可以先使用逻辑位置记录，例如：

-   衣柜 / 上层
-   衣柜 / 左侧
-   书架 / 第二层
-   收纳柜 / 下层抽屉

这些逻辑位置可以先通过列表或文本字段表达，不必全部制作成三维模型。

## 6. 空间展示关系与物品存放关系

需要区分两个概念：

### 6.1 三维展示关系

描述哪些家具模型被放置在当前房间中，以及它们在场景中的位置和朝向。

``` text
房间场景
├── 衣柜模型
├── 书架模型
├── 书桌模型
└── 沙发模型
```

### 6.2 物品存放关系

描述物品实际存放在哪个家具或逻辑位置中。

``` text
房间
├── 衣柜
│   └── 物品
├── 书架
│   └── 物品
└── 书桌
    └── 物品
```

两种关系不应被强制设计成完全相同的结构。

例如，家具在三维场景中可以只是一个整体模型；其内部的抽屉、隔层和收纳盒可以先作为逻辑存放位置管理，不必都拥有独立三维模型。

## 7. 第一版功能范围（MVP）

### 7.1 必须实现（P0）

  模块       第一版要求
  ---------- ------------------------------
  房间视图   固定等距轴测视角
  房间表现   简化墙面、地板及房间轮廓
  家具模型   提供一批常用家具模型
  家具添加   从家具库选择并添加
  家具摆放   支持触屏拖动调整位置
  家具旋转   支持简单旋转
  家具选择   点击家具可选中
  家具信息   展示家具名称及绑定物品数量
  物品绑定   将物品绑定到家具
  物品查看   从家具进入已绑定物品列表
  位置修改   支持修改物品的存放家具
  数据保护   删除家具时不静默删除物品记录

### 7.2 可以延期（P1）

-   更多家具模型和外观。
-   家具尺寸的精细调整。
-   家具内部逻辑分区的可视化。
-   多个房间之间的快速切换优化。
-   有限的其他观察视角。
-   家具模型的自定义上传。
-   2D 平面图与三维视图联动。

### 7.3 第一版明确不做

-   专业 CAD/BIM 编辑能力。
-   自由建模和墙体编辑。
-   自由旋转三维摄像机。
-   复杂 XYZ 坐标编辑。
-   物理模拟。
-   家具内部真实结构建模及开合动画。
-   每件物品独立三维建模。
-   AI 自动生成精准完整的全屋三维模型。
-   多人实时协同编辑。

## 8. 移动端体验要求

本项目面向小程序，交互设计必须优先考虑触屏使用：

-   可点击家具应有足够的触控区域。
-   拖动家具时，应避免误触页面滚动或其他家具。
-   家具选中状态应清晰。
-   家具操作尽量通过少量按钮或底部操作区完成。
-   不依赖悬停交互。
-   不要求用户输入坐标或使用键盘快捷键。
-   家具库采用适合手机浏览的卡片或列表形式。
-   三维场景加载失败时，仍应提供列表形式的家具和物品管理入口。

## 9. 交互验收标准

第一版至少应通过以下验收：

1.  用户可以打开一个房间，并看到固定等距视角的三维场景。
2.  用户可以从家具库添加家具。
3.  用户可以在场景中选中家具。
4.  用户可以调整家具位置。
5.  用户可以调整家具朝向。
6.  用户可以查看选中家具的名称及绑定物品数量。
7.  用户可以将已有物品绑定到家具。
8.  用户可以从家具入口查看绑定的物品。
9.  用户可以修改物品的存放家具。
10. 删除家具时，系统不会静默删除关联物品记录。
11. 三维视图不可用时，物品记录仍然可以通过列表方式访问和管理。

## 10. 技术与实现约束

本节只定义产品层面的约束，不指定最终技术框架：

-   三维场景采用固定等距视角。
-   家具模型应可独立选择和操作。
-   家具场景位置、朝向等展示属性应与物品业务数据分开管理。
-   物品绑定关系不依赖三维模型文件本身。
-   三维模型加载失败或暂不可用，不应导致物品数据不可访问。
-   家具模型资源应统一风格，并控制资源体积，适配小程序加载性能。
-   坐标系、单位、模型原点、家具旋转规则等技术细节应在开发技术方案中统一定义，避免不同模型资源之间出现摆放偏差。

## 11. 设计原则总结

本项目三维空间视图遵循以下原则：

1.  **轻量化：** 只实现物品管理真正需要的三维能力。
2.  **直观化：** 用户通过熟悉的家具识别存放位置。
3.  **固定视角：** 采用等距轴测房间视图，减少复杂视角操作。
4.  **家具优先：** 家具是三维场景的主要交互对象。
5.  **物品为核心：** 三维模型是入口，物品记录和存放关系才是业务核心。
6.  **关系分离：** 三维展示结构与物品存放关系不强制绑定为同一结构。
7.  **移动端优先：** 所有核心操作适配小程序触屏。
8.  **可降级：** 三维视图不可用时，基础物品管理仍可正常使用。

## 12. 最终设计定义

> 采用固定等距轴测视角的轻量化三维房间场景，以家具作为物品管理的主要交互对象。用户通过添加、摆放家具建立可视化存储空间，并通过点击家具绑定、查看和管理物品。第一版不提供专业三维建模能力，不要求每件物品拥有独立三维模型。三维视图服务于物品管理，而不是成为物品管理的使用门槛。

**本规范作为三维空间视图 V1.0
的设计基准。后续页面原型和开发实现应遵循本规范；如需扩大功能范围，应先明确变更原因、用户价值及对
MVP 范围的影响。**
