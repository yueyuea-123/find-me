## 一、决策背景

视觉重要性确认后，对两条路线做了实测对比：

| 项 | 自建 WebGL 增强 | 切换 Three.js |
|---|---|---|
| 包体 | 新增 19KB，主包仍 1.8M / 2M | three.min 671KB，主包超限需分包 |
| 已验收资产 | 21 页、绑定一致性、模板、降级路径全部保留 | 渲染层重写，需全量回归 |
| 风格实现 | 圆角、色板、接触阴影、正交视角均可原生实现 | 可复用预览代码，但该风格用不上大部分引擎能力 |
| 风险 | 增量改动，可回退 | 包体、分包加载、真机兼容三重风险 |

结论：**保留自建 WebGL 渲染器并做视觉增强**。Three.js 继续作为独立风格验证载体（`preview/`），不进小程序运行时。

## 三、规范落地对照

| 规范项 | 增强渲染器实现 |
|---|---|
| 3.2 尺寸基准 | 沿用 `furniture.size`，未改数据契约 |
| 3.3 配色板 | 内置色板常量；`colorOf()` 将既有 variant 名映射到规范色 |
| 3.4 材质光照 | 哑光着色器：半球环境光 + 方向光；程序化渐变接触阴影贴图 |
| 3.5 视角 | 正交投影，yaw 0.7（约 40°）、pitch 0.52（约 30°） |
| 造型 | 圆角盒几何（每部件 576 顶点）；按 category 组合 2～15 个部件 |
| 前墙隐藏 | 仅保留后墙与左墙，半透明 |

## 四、兼容与回退

- **默认关闭增强视觉**：进入页面仍是原渲染器，行为与已验收版本一致。
- **开关切换**：用户在模式栏点「增强视觉」进入新渲染器，再点回「经典视觉」回退。
- **失败回退**：增强渲染器 WebGL/着色器初始化失败时自动切回原渲染器并提示，不进入列表降级。
- **接口一致**：`render/resize/pick/orbit/pan/zoom/reset/getSelected/setSelected` 全部实现，`_safeGL` 调用无需改动。
- **绑定不变**：模型与逻辑节点解耦（BR-009）保持，换渲染器不影响物品与收纳节点关联。
