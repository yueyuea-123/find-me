**本规范覆盖：浏览、选中、家具直接拖拽、按钮微调、家具数量角标、家具管理入口、视图切换、保存、异常状态及开发验收。**

## 0. 本次冻结的关键决策

| 项目 | V1.4 决策 |
|---|---|
| 交互方向 | 直接拖拽为主、按钮微调为辅（推翻 V1.3 的 A 方案） |
| 家具选中 | 点击（短按）家具一次，显示选中态和底部物品面板 |
| 进入家具管理 | 选中后点击明确的“管理”按钮；不采用双击 |
| 家具移动 | **单指直接拖动家具**，实时跟手，抬手落盘并按 5cm 网格吸附；方向按钮保留为精确定位备选 |
| 家具旋转 | **双指旋转手势**作用于选中家具，抬手落盘；±15°/90°角度按钮保留为精确备选 |
| 家具尺寸 | 进入尺寸编辑，输入长、宽、高；不提供自由缩放手柄 |
| 相机控制 | 空白单指拖动转视角、双指张开/捏合缩放视角；相机变化不算家具数据变更 |
| 工具互斥 | 拖拽手势与方向/角度按钮不同时使用；尺寸编辑时禁用场景手势 |
| 保存 | 拖拽/旋转抬手即落盘并记入撤销栈；支持撤销、放弃修改回滚 |
| 家具数量角标 | 三维家具顶部显示“内有 N 件”（取有效物品数），0 件不显示；底部卡片同步显示数量 |
| 删除 | 通过家具管理入口执行，必须确认并检查收纳位置/物品关系 |

**重要调整：** “缩放”仍以“尺寸”形式提供（长、宽、高数值编辑），不使用容易误触的三维缩放手柄。相机缩放（双指张开/捏合）与家具尺寸编辑是两回事，前者只改变视角、不改家具。

## 1. 页面目标与非目标

### 页面目标
1. 一眼看清房间与家具的相对位置。
2. 通过点击选择家具，并快速进入家具管理。
3. 用户能以低学习成本完成家具的基本位置和角度调整。
4. 用户能切换到当前空间的物品清单，查看物品归属。
5. 所有场景编辑都可保存、撤销或放弃，不产生隐式数据丢失。

### 首版非目标
- 不做专业 3D 建模、自由轴向 Gizmo 或任意轴拖拽（仅地面平面内的移动/绕垂直轴旋转）。
- 不做家具碰撞模拟、自动避障或房间尺寸自动识别。
- 不做 AR 扫描、自动识别房间、自动识别家具。
- 不做多人实时协同编辑。
- 不在场景主视图里直接编辑柜体内部每个格子的几何结构；内部收纳位置在家具管理页维护。

### 布局比例建议
以 750rpx 逻辑宽度为基准，按可用高度自适应，不将以下数值作为固定像素：
- 顶部导航与视图切换：约占可用高度 10%–14%。
- 三维场景：约占可用高度 54%–62%，必须是视觉主体。
- 底部列表/操作面板：约占可用高度 24%–30%。
- 安全区和固定操作区单独计算，不覆盖系统手势区域。

场景区域优先保证完整看到主要家具。底部面板可在“半展开/收起”之间切换；首版不做复杂多级拖拽面板。

## 3. 默认浏览模式

### 3.1 用户操作
- 短按（点击且不拖动）家具：选中该家具并弹出底部物品面板。
- 单指拖动家具：直接移动该家具，实时跟手；抬手落盘并按 5cm 网格吸附。
- 点击场景空白处：取消选中。
- 单指拖动空白场景：旋转相机视角。
- 双指张开/捏合：缩放相机视角，不改变家具尺寸。
- 双指旋转手势：在已选中家具时旋转该家具，抬手落盘；未选中家具时不旋转场景。
- 点击“复位”：回到当前空间默认视角。
- 点击“适配”：将房间及当前空间家具整体放入可视范围。
- 点击视角预设：切换等距视角 / 正面视角 / 俯视角（首版可先实现等距和俯视两个预设）。

### 3.2 关键约束
- 只有触摸到家具可交互区域才触发选中或拖动；点到地面或墙面属于空白场景手势。
- 命中家具的单指拖动只移动家具，不同一次手势中转成相机拖动。
- 命中家具的位移在抬手时才写入数据层（一次性落盘），拖动过程只更新渲染预览，避免每帧写数据造成卡顿。
- 落盘位置按 5cm 网格吸附；旋转落盘同样在抬手时进行。
- 相机操作只在空白场景上生效，且不算家具数据变更。
- 视图正在加载或保存时，暂时禁用会造成状态冲突的编辑动作。
- 相机视角变化不标记为家具数据变更；除非产品明确要求保存用户自定义相机视角。

## 4. 家具选中模式

点击家具后进入选中模式：
- 被选家具显示清晰轮廓描边或柔和底部高亮。
- 其他家具保持正常显示，不整体变暗。
- 显示家具名称，例如“电视柜”。
- 在场景下方显示轻量操作面板：`管理 / 移动 / 旋转 / 尺寸`。
- 底部家具列表同步滚动并高亮对应卡片。
- 点击空白处退出选中；点击另一家具切换选中目标。

**不使用双击进入管理。** 双击在手机上容易误触，且与场景相机手势冲突。用户选中后通过“管理”明确进入家具管理页。

**短按与拖动的区分：** 触摸家具后位移未超过阈值即视为短按（选中并弹面板）；超过阈值则视为拖动（移动家具），同一次手势只走其中一条路径，不相互串扰。短按弹面板这条找物主路径在 V1.4 中保持不变。

## 5. 家具编辑方式（直接拖拽为主、按钮微调为辅）

### 5.1 移动：直接拖拽

主路径：在家具视图或选中态下，单指按住家具直接拖动，模型实时跟手；抬手时一次性写入位置数据并按 5cm 网格吸附。拖动过程只更新渲染预览，不逐帧写数据，以避免卡顿。

辅助路径：选中家具 → 点击“移动”，用方向按钮做精确定位。

界面：
- 拖动时家具保持选中描边，数量角标随模型一起移动。
- 方向控制区保留：前、后、左、右，每次固定步长 5cm，作为拖拽后的微调手段。
- 拖动或按钮移动的结果一致，均进入同一撤销栈，可撤销、可放弃修改回滚。

边界：
- 移动仅在地面平面进行，不允许用户沿 Y 轴抬高家具。
- 家具位置使用场景世界坐标保存；界面显示以 cm 为单位的平面位置仅作为调试信息，普通用户不必看到坐标。
- 落盘按 5cm 网格吸附，属于首版隐含规则；贴墙、靠边等更强吸附另立需求。

### 5.2 旋转：双指手势为主、按钮为辅

主路径：选中家具后，双指旋转手势作用于该家具，抬手一次性落盘。

辅助路径：选中家具 → 点击“旋转”，用按钮精确旋转。

界面：
- 保留旋转方向按钮：逆时针 / 顺时针。
- 每次点击按钮默认旋转 15°；提供 90°快捷按钮。
- 显示当前角度，建议以 0°–359°显示。

边界：
- 首版只绕垂直轴旋转，不支持翻倒、倾斜或三轴旋转。
- 旋转中心由家具模型定义，默认使用模型底部几何中心。
- 旋转前后家具仍落在地面平面，不改变高度。
- 双指张开/捏合只缩放相机视角，不旋转家具、不改家具尺寸；旋转手势与缩放手势按双指运动特征区分。

### 5.3 尺寸模式

入口：选中家具 → 点击“尺寸”。

界面：
- 打开底部尺寸编辑面板。
- 三个字段：长、宽、高，单位 cm。
- 显示当前尺寸；修改后预览模型变化。
- 点击“应用”写入本地待保存状态；点击“取消”放弃本次尺寸修改。

边界：
- 不提供自由拖拽缩放控制点。
- 长宽高必须大于 0；最大值和输入精度由产品/技术配置定义。
- 修改尺寸时保持家具底部中心锚点不变，避免家具看起来突然漂移。
- 模型若不支持非等比缩放，应按模型能力锁定比例并明确告知；不能静默变形。
- 尺寸变更与场景模型尺寸同步，家具管理页读取同一份尺寸数据。

### 5.4 家具数量角标

- 三维场景中，每件家具模型上方显示“内有 N 件”角标，N 取该家具下有效物品数（有效口径沿用物品规则：归档物品不计入）。
- 角标随家具一起移动、随相机旋转实时更新位置，数据变化时同步刷新。
- N 为 0 时不显示角标，避免空家具造成画面杂乱。
- 底部家具卡片的右上角同步显示同一数量。
- 角标只提示“有几件”，不把物品画成三维模型、不显示物品名称；查看具体物品仍走“点家具弹底部面板”主路径。
- 角标是纯展示层：不参与拾取点击（点角标等同于点该家具），不动物品与收纳节点的绑定关系。

## 6. 模式状态机

```text
LOADING
  └─加载成功→ VIEW
VIEW / SELECTED（家具视图主交互态）
  ├─短按家具→ SELECTED（选中并弹底部物品面板）
  ├─拖动家具→ 实时预览，抬手落盘并吸附（停留在本态）
  ├─双指旋转已选家具→ 抬手落盘（停留在本态）
  ├─单指拖动空白/双指缩放→ 相机操作（停留在本态）
  ├─点击空白→ VIEW
  ├─管理→ NAVIGATE_FURNITURE
  ├─移动/旋转/尺寸按钮→ MOVE / ROTATE / DIMENSION（微调）
  ├─切换物品→ ITEM_VIEW
  ├─保存→ SAVING
  ├─撤销→ 回退最近一次拖拽/微调
  └─退出页面→ 检查是否有未保存变更
MOVE / ROTATE / DIMENSION（按钮微调子态）
  ├─完成→ SELECTED（保留改动，可继续拖拽）
  └─取消→ SELECTED（回滚本次微调）
SAVING
  ├─成功→ SELECTED（清除 dirty 标记）
  └─失败→ SAVE_ERROR（保留本地改动）
ITEM_VIEW
  ├─点击物品→ ITEM_DETAIL
  └─切回家具→ VIEW
```

### 状态定义
| 状态 | 允许操作 | 禁止/限制 |
|---|---|---|
| LOADING | 取消返回 | 禁止编辑 |
| VIEW | 相机操作、短按选家具、拖动家具、切视图 | 拖动只改位置/角度，不动物品绑定 |
| SELECTED | 管理、拖动/旋转、方向/角度/尺寸微调、保存、撤销 | 不允许多个家具同时选中 |
| MOVE | 方向按钮微调、取消、完成 | 禁止相机旋转和其他变换 |
| ROTATE | 角度按钮微调、取消、完成 | 禁止移动和尺寸编辑 |
| DIMENSION | 编辑长宽高、应用、取消 | 禁止场景手势编辑 |
| SAVING | 等待结果 | 禁止重复保存和冲突编辑 |
| SAVE_ERROR | 重试保存、继续编辑、撤销 | 不清除本地变更 |
| ITEM_VIEW | 搜索/筛选/查看物品 | 不显示家具变换工具 |

## 7. 保存、撤销和离开页面

### 保存策略
- 本项目为个人单机使用、数据存本机，无服务端，不存在服务端版本号与云端提交。
- 拖拽抬手或按钮微调完成后，位置/角度/尺寸的改动即时写入本地数据层（每次改动即提交），因此**刷新或退出不会丢失已完成的摆放**。
- 发生实际数据变化时设置 `isDirty = true`，并将其记入撤销栈。
- “保存”按钮的作用是一次显式确认：清空撤销栈、`isDirty = false`、刷新场景；它不改变“改动已落盘”这一事实。
- 保存失败（本地写入异常）时保留改动并提示，可重试。
- 进入编辑模式但没有实际修改，不应标记为 dirty。

### 撤销策略
只要求撤销最近一次已完成的家具变更（拖拽、旋转或尺寸应用），撤销栈按此维护；不要求完整多级历史时间线。
- 撤销后更新场景和列表显示。
- 撤销本身也应成为新的待保存状态，除非它恢复到了最后保存版本。
- 不在编辑子模式中同时执行撤销；先完成或取消当前编辑。

### 离开页面
若 `isDirty = false`：直接离开。  
若 `isDirty = true`：弹出确认：
- 保存并离开
- 放弃修改并离开
- 继续编辑

## 8. 家具视图与物品视图

### 家具视图（默认）
- 场景中显示家具，以及每件家具的数量角标（见 §5.4）。
- 底部面板展示家具卡片，卡片右上角同步显示数量。
- 点击家具卡片：场景定位并选中对应家具。
- 卡片显示缩略图、家具名称和数量；数量角标只是入口提示，具体物品仍走点家具弹面板。

### 物品视图
- 不要求三维场景把每件小物品都渲染成 3D 模型。
- 首版采用“场景弱化 + 物品列表”的方式：保留空间背景或简化场景，底部显示当前空间物品列表。
- 每项显示物品图片/占位、名称、数量、家具名称、收纳位置。
- 未绑定位置时显示“未设置位置”。
- 点击物品进入物品详情。
- 切换视图不改变物品数据，不重新创建物品记录。

## 9. 数据与开发接口建议

### 9.1 家具实例数据
```ts
type FurnitureInstance = {
  id: string;
  spaceId: string;
  modelId: string;
  name: string;
  position: { x: number; y: number; z: number };
  rotationY: number; // radians or degrees: project-wide choose one, do not mix
  dimensionsCm: { length: number; width: number; height: number };
  modelScale: { x: number; y: number; z: number }; // derived from dimensions and model base size
  updatedAt: string;
  version: number;
};
```

### 9.2 前端场景状态
```ts
type SceneMode =
  | "loading"
  | "view"
  | "selected"
  | "move"
  | "rotate"
  | "dimension"
  | "saving"
  | "saveError"
  | "itemView";

type SceneState = {
  mode: SceneMode;
  selectedFurnitureId: string | null;
  activeTool: "move" | "rotate" | "dimension" | null;
  isDirty: boolean;
  pendingChanges: Record<string, Partial<FurnitureInstance>>;
  cameraPreset: "isometric" | "top" | "front";
};
```

### 9.3 建议接口边界
接口路径仅作职责示例，需结合现有后端约定：
- `GET /spaces/{spaceId}/scene`：获取空间场景、家具实例和模型引用。
- `PATCH /furniture-instances/{id}`：更新单件家具位置、角度或尺寸。
- `POST /spaces/{spaceId}/scene/save`：如采用批量保存，则一次提交场景变更集合。
- `GET /spaces/{spaceId}/items`：获取当前空间物品列表。

首版建议优先采用“场景一次批量保存”或“单家具变更提交”中的一种，避免两种保存策略并存。若存在并发编辑，使用 `version` 做乐观锁，冲突时提示刷新或保留本地副本。

## 10. 三维渲染层与业务层解耦

建议拆分为以下模块，不把业务规则直接写进 3D 引擎事件回调：

1. `ScenePage`：页面布局、导航、视图切换。
2. `SceneCanvas`：只负责场景渲染、相机和射线命中测试。
3. `FurnitureSelectionController`：维护当前选中家具。
4. `FurnitureTransformController`：执行移动步进、旋转步进、尺寸应用。
5. `SceneStateStore`：唯一场景状态源，供场景和 UI 共用。
6. `SceneRepository`：加载、保存、重试、版本冲突处理。
7. `AssetManager`：模型/缩略图加载、缓存、失败占位。

**原则：** 3D 场景点击只返回命中的 `furnitureId`，由业务状态层决定进入哪个模式；按钮事件只调用业务命令，由渲染层更新模型。避免 UI 与 3D 模型各自维护一套选中状态。

## 11. 性能与降级要求

- 优先加载当前空间可见的模型，不预加载整个家庭所有模型。
- 家具缩略图与 3D 模型分开加载；缩略图先显示，模型随后补齐。
- 单个模型加载失败时显示占位，不应导致整个场景失败。
- 进入页面先显示静态场景占位或加载骨架，避免白屏。
- 场景失去前台时暂停不必要的渲染循环；恢复前台后重新校验状态。
- 对低性能设备提供降级策略：减少阴影、降低纹理分辨率、减少后处理；必要时切换静态预览并保留家具列表管理。
- 首版不以帧率数字作为产品承诺；需在目标机型上建立性能验收基线。

## 12. 开发验收清单

### 浏览与选择
- [ ] 默认进入家具视图，场景加载完成后可操作。
- [ ] 短按家具一次即可选中并弹出底部物品面板，选中轮廓清楚。
- [ ] 点击空白处取消选中。
- [ ] 点击另一家具时选中对象正确切换。
- [ ] 家具列表卡片与场景选中状态双向同步。
- [ ] 选中后通过“管理”按钮进入家具管理，不依赖双击。

### 相机
- [ ] 空白区域单指拖动只旋转相机。
- [ ] 双指张开/捏合只改变相机距离，不改变家具尺寸。
- [ ] 短按家具不会触发相机旋转。
- [ ] 复位、适配和视角预设可用。
- [ ] 相机变化不错误标记为家具数据 dirty。

### 家具直接拖拽与微调
- [ ] 家具上单指拖动可实时跟手移动，抬手后落盘并按 5cm 吸附。
- [ ] 拖动已选中家具的双指旋转手势生效，抬手落盘。
- [ ] 拖动/旋转全过程不破坏收纳节点与物品绑定（BR-009）。
- [ ] 方向按钮（5cm）、角度按钮（±15°/90°）作为精确微调仍可用，结果与拖拽一致。
- [ ] 尺寸通过长宽高字段修改，不出现自由缩放手柄。
- [ ] 拖拽抬手后改动即时落盘，刷新不丢失。
- [ ] 撤销可回退最近一次拖拽/微调；放弃修改可回滚。
- [ ] 拖动与按钮微调不会同时进行；尺寸编辑态禁用场景手势。

### 家具数量角标
- [ ] 每件有物品的家具顶部显示“内有 N 件”，N 为有效物品数。
- [ ] N 为 0 时不显示角标。
- [ ] 角标随家具移动和相机旋转实时更新位置。
- [ ] 底部卡片右上角同步显示数量。
- [ ] 角标不显示物品名称、不把物品画成三维模型；点家具仍弹面板看物品。

### 保存与异常
- [ ] 保存中不可重复提交。
- [ ] 保存失败保留本地修改并可重试。
- [ ] dirty 状态下离开页面会二次确认。
- [ ] 模型单体加载失败不影响其他家具。
- [ ] 空空间有添加家具入口。
- [ ] 低性能降级时仍可查看家具列表和进入家具管理。

### 物品视图
- [ ] 物品列表仅显示当前空间内物品。
- [ ] 每项显示家具与收纳位置归属。
- [ ] 未绑定位置的物品显示“未设置位置”。
- [ ] 点击物品进入正确的物品详情。
- [ ] 切换视图不改变物品绑定关系。

## 13. 待技术选型前确认的事项

以下内容本规范不擅自锁定，需在正式开发技术方案中确定：
1. 3D 渲染引擎及微信小程序运行适配方式。
2. 家具模型格式、压缩方式、纹理规格与资源托管。
3. 世界坐标单位、地面平面轴向、模型原点与旋转中心。
4. 场景保存采用批量提交还是单家具提交。
5. 目标机型范围和低性能降级阈值。
6. 是否需要保存用户自定义相机视角。

在这些事项确认前，交互和业务状态可以先按本规范开发，3D 引擎通过适配层接入。
