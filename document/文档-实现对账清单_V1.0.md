# 文档-实现对账清单 V1.0

> **依据**：《当前基线（唯一口径）V1.1》、《整改排期 V1.0》B1 产出。
> **用途**：逐页核对设计文档、交互规范与代码实现的一致性，标记"有/无/冲突"，作为 B3/B4 代码整改的输入。
> **标记口径**：
> - **有**：设计/交互/实现均存在且与基线 V1.1 一致。
> - **无**：该维度在基线中不要求或已移出范围。
> - **冲突**：存在但与基线 V1.1 不一致，需在对应批次整改。
> **页面范围**：以 `app.json` 注册的 21 页为准（基线 §3）。
> **修订（2026-11-24）**：本清单编制时三维交互尚处 V1.3 A 方案（禁拖拽+草稿保存）。现行三维交互基准已变更为《客厅三维空间交互与开发设计规范 V1.4》（直接拖拽为主、按钮微调为辅），room3d 相关条目与 B4 批次已按 V1.4 复核改写；其余批次（B2/B3）整改均已完成。与 V1.4 冲突处一律以 V1.4 为准。

## 冲突明细

### B2 批次：云端能力下线/降级

| 页面 | 冲突点 | 整改动作 |
|---|---|---|
| profile | `app.js` 启动期调用 `cloud-sync.js`；页面含云同步状态入口 | 摘除 `cloud-sync` 引用；隐藏/降级云端入口，保留本地备份入口 |
| backup | 云端定时快照备份能力 | 降级为本地备份导出/恢复；移除云端备份相关 UI 与逻辑 |
| admin | 云端任务统计/用户管理 | 降级为本地错误日志查看或隐藏页面入口 |

### B3 批次：物品归属模型落地

| 页面 | 冲突点 | 整改动作 |
|---|---|---|
| item-edit | 物品 `spaceId` 必填；`anchorType` 三态互斥；不持有坐标与 `roomId` | 实现 `anchorType` 字段；校验 `spaceId`；移除物品坐标字段写入 |
| item-detail | 未显示 `anchorType` 标签 | 显示锚点类型标签（挂家具/空间直挂/未放置） |
| furniture-detail | 删除家具时物品未转入 `unplaced` | 删除家具时，其下物品 `anchorType` 改为 `unplaced`，保留 `spaceId` |
| index | 房间物品计数口径 | 房间物品数 = 锚定该房间家具的物品数（按 id 去重） |

### B4 批次：三维呈现层收口（已按 V1.4 收口，2026-11-24）

> 原本节按 V1.3 A 方案（禁拖拽、草稿保存）编写，与 2026-11-24 生效的《客厅三维空间交互与开发设计规范 V1.4》直接冲突。V1.4 已推翻 A 方案、恢复直接拖拽（详见 V1.4 头部变更说明），本节整改动作相应改写如下；原旧口径文字作废，不得再作为重构依据。

| 页面 | 冲突点（按 V1.4 现行口径复核） | 整改动作（已完成） |
|---|---|---|
| room3d | 原判"可能残留拖动家具路径"基于禁拖拽旧口径，已失效 | V1.4 要求**直接拖拽为主**：单指拖动家具实时跟手、抬手落盘并按 5cm 吸附；双指旋转选中家具、缩放视角；方向/角度按钮降为精确微调。实现已按此落地并通过 `stage2-drag-badge-test` 23/23 |
