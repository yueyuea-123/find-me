## 四、数据模型与字段口径

### 4.1 内存状态对象

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 空间 spaces | `id`、`name`、`archived` | 当前空间由 `activeSpaceId` 指定 |
| 房间 rooms | `id`、`spaceId`、`name`、`width`、`depth`、`height`、`templateKey`、`floor{x,y,w,h}` | 宽深高为布局输入；`floor` 为户型网格位置与跨度（单位：格）；`templateKey` 取 `bedroom`/`living`/`bath` 或空 |
| 家具 furniture | `id`、`roomId`、`category`、`name`、`model`、`position{x,y,z}`、`rotation`、`size{w,h,d}`、`status` | 外观模型与逻辑节点解耦；`status` 为 `confirmed` |
| 节点 nodes | `id`、`roomId`、`furnitureId`、`parentId`、`name`、`type` | 多级树；`type` 取"家具""抽屉/隔层""收纳盒" |
| 物品 items | `id`、`name`、`category`、`trackingMode`、`currentNodeId`、`locationStatus`、`managementStatus`、`completed`、`note`、`updatedAt` | 单物件单位置；`managementStatus` 取 `active`/`ended` |
| 移动 movements | `id`、`itemId`、`type`、`fromNodeId`、`toNodeId`、`fromStatus`、`toStatus`、`note`、`createdAt` | 当前位置与历史同事务写入 |
| 库存 inventory | `itemId`、`balance`、`unit`、`threshold` | 余额不得为负 |
| 交易 transactions | `id`、`itemId`、`type`、`delta`、`balanceAfter`、`note`、`createdAt` | 调整与消耗分开记录 |
| 提醒 alerts | `id`、`itemId`、`status`、`createdAt`、`recoveredAt` | `status` 取 `pending`/`ignored`/`recovered`；`recoveredAt` 为恢复时间 |

### 4.2 关键枚举（界面选项与显示值）

| 枚举 | 取值（内部 → 界面显示） |
| --- | --- |
| 跟踪模式 TRACKS | `location`→只记位置、`inventory`→只记库存、`hybrid`→位置+库存 |
| 位置状态 STATUS | `at_home`→在家、`unknown`→位置未知、`out`→外出携带、`borrowed`→借出 |
| 交易类型 TX | `in`→入库、`consume`→消耗、`adjust`→调整 |
| 移动类型 MV | `initial`→初始存放信息、`first_confirm`→首次位置确认、`move`→移动、`out`→外出/借出、`return`→带回/归还、`end`→结束管理 |
| 物品分类 CATS | 证件卡片、家居布艺、电子数码、卫浴清洁、书籍文具、其他 |
| 计量单位 UNITS | 个、件、瓶、包、盒、卷 |
| 场景模板 TEMPLATES | 卧室 `bedroom`（双人床、床头柜、落地窗）、客厅 `living`（三人沙发、茶几、电视柜）、卫生间 `bath`（浴室收纳盒、镜柜抽屉） |
| 家具模型库 LIB | 床、床头柜、台灯、窗帘、沙发、茶几、电视柜、衣柜、书架、收纳盒、抽屉（各带默认尺寸 宽×高×深） |

### 4.3 户型网格口径

- 网格为 6 列（`FLOOR_COLS = 6`）、最多 8 行（`FLOOR_MAX_ROWS = 8`）；房间块以 `{x, y, w, h}` 表示起点与跨度（单位：格）。
- 无 `floor` 的房间按创建顺序回退到默认槽位；新建房间自动在左上角起扫描第一个可放下 3×2 的空位。
- 房间块带 8 个缩放把手：四角 `nw/ne/se/sw` + 四边中点 `n/e/s/w`。
- 越界（超出 6 列或 8 行）或与其他房间重叠均判为非法布局，不写入状态。
- 界面明示"墙线为示意，不承诺测量精度"。

## 五、流程说明

### 5.1 主路径

六条流程（5 条主路径 + 1 条异常与降级）进度独立；每条步骤顺序执行，界面随每步真实变更数据并刷新数据快照。

#### UF-001 首次建立空间

目标：建空间 → 建房间（宽深高）→ 选起点 → 三维加家具 → 编辑保存。共 6 步。

| # | 步骤 | 状态提示（界面原文案） |
| --- | --- | --- |
| a) | 打开空间列表 | 支持创建多个空间；首版仅个人单用户。 |
| b) | 新建空间「演示·新居」 | 空间是最高层级，其下可建多个房间。 |
| c) | 新建房间「书房」并填宽深高 | 尺寸为布局输入，不承诺测量精度；无模型时房间仍可存在。 |
| d) | 为书房应用「卧室模板」 | 模板家具为普通可编辑对象，不锁定；模板缺失可降级空白房间。 |
| e) | 从模型库添加家具 | V1.2 主路径：手动添加，可先用占位模型；不依赖照片。 |
| f) | 拖动 / 旋转 / 缩放并保存 | 越界自动钳制；重进后位置与尺寸保持一致。 |

#### UF-002 家具与收纳

目标：建收纳节点 → 绑定物品 → 换模型不动逻辑节点。共 5 步。

| # | 步骤 | 状态提示（界面原文案） |
| --- | --- | --- |
| a) | 打开床头柜详情 | 家具本身即逻辑位置节点；模型与逻辑位置分离。 |
| b) | 创建收纳节点「证件隔层」 | 多级位置树：家具 → 抽屉/隔层 → 收纳盒。 |
| c) | 将「身份证」绑定到该节点 | 单物件单位置；绑定沿 nodes.furnitureId + items.currentNodeId 单源表达。 |
| d) | 点选模型查看关联物品 | 从三维选中模型可直接看到关联物品与节点。 |
| e) | 更换外观模型验证解耦 | 换模型后节点与物品关联保持不变（MVP-016）。 |

#### UF-003 添加物品

目标：仅名称建档 → 渐进完善 → 保存并继续 → 搜索查看。共 5 步。

| # | 步骤 | 状态提示（界面原文案） |
| --- | --- | --- |
| a) | 打开物品建档页 | 只需名称即可建档，降低一次性录入负担。 |
| b) | 仅填名称保存「演示·数据线」 | 分类、照片、位置可后续补充，档案完整度随之提高。 |
| c) | 打开新建页演示"保存并继续" | 连续建档时每件独立建档，可保留默认家具/节点。 |
| d) | 渐进完善刚建的档案 | 位置一次填写属初始存放信息，不记为移动。 |
| e) | 搜索并查看位置 | 列表支持按名称/分类搜索；未知状态明确显示。 |

#### UF-004 移动物品

目标：详情 → 移动 → 选目标并确认 → 同事务更新位置与历史。共 5 步。

| # | 步骤 | 状态提示（界面原文案） |
| --- | --- | --- |
| a) | 打开「身份证」详情 | 当前位置为用户确认事实，移动须用户显式确认。 |
| b) | 进入移动页 | 目标可为具体位置，也可为外出/借出等状态。 |
| c) | 选择目标位置「上层抽屉」 | 移动前的位置来自历史确认，不自动推断。 |
| d) | 确认移动 | 当前位置与历史在同一事务写入，两者保持一致。 |
| e) | 查看位置历史 | 历史可追溯；首次位置确认单独成类，不伪装为移动。 |

#### UF-005 库存管理

目标：入库/消耗/调整 → 库存不为负 → 交易流水 → 阈值提醒。共 5 步。

| # | 步骤 | 状态提示（界面原文案） |
| --- | --- | --- |
| a) | 打开库存总览 | 低库存条目置顶；余额与阈值一目了然。 |
| b) | 查看「洗发水」库存详情 | 每次变化都留交易记录，调整与消耗分开。 |
| c) | 消耗 4 瓶（触发不足拦截） | 当前仅 1 瓶，消耗会导致余额为负 → 拒绝，纠错走调整。 |
| d) | 入库 3 瓶 | 入库增加余额并生成一条交易，提醒自动恢复。 |
| e) | 检查提醒自动恢复 | 补货使余额高于阈值后，当前提醒周期自动结束。 |

### 5.2 异常与降级流程

目标：验证关联保护、三维降级、首次位置确认与库存约束。共 4 步。

| # | 步骤 | 状态提示（界面原文案） |
| --- | --- | --- |
| a) | 删除含物品的节点 → 阻断 | 上层抽屉含身份证，删除被阻断并提示先迁移/归档。 |
| b) | 三维不可用 → 切列表 | 列表视图下家具与位置管理仍可完成。 |
| c) | 未知首次确认 → 独立事件 | 备用钥匙原本位置未知，确认到具体位置记为 first_confirm。 |
| d) | 结束管理需处置剩余库存 | 有余额时须先明确处置方式，不能伪装成消耗。 |

## 六、逐页界面说明

### 6.1 首页（home）

- **入口/返回**：底部 tab"首页"；右上角"康"进入提醒中心。
- **字段与信息**：

- **交互**：

- **提示文案**：非编辑态"点击房间查看三维 · 可「编辑布局」调整房间排布"；图例"家具 / 物品数 / 墙线为示意，不承诺测量精度"；无变动时"暂无变动，去建一份档案吧"。

### 6.2 空间列表（space）

- **字段**：空间卡片（名称、"N 个房间 · 个人空间"、当前空间高亮并标"当前"）。
- **交互**：点击卡片切换当前空间并进入房间页；底部"＋ 新建空间"弹出确认层（标题"新建空间"，说明"支持多个空间，首版仅个人使用"；按钮"取消"/"创建"；名称为空提示"请输入名称"，成功提示"空间已创建"）。
- **提示**：首版仅支持个人单用户，不支持家庭成员共享；可创建多个空间分别管理。

### 6.3 房间（room）

- **字段**：房间卡片（名称、`宽×深×高 m`、家具数、"场景模板/空白房间"标签、"用户确认事实"标签）；无房间显示"还没有房间，先建一个吧"。
- **交互**：
  - a) 点击房间卡片进入三维房间；
  - b) "空间列表"进入空间列表；
  - c) "＋ 新建房间"弹出确认层：标题"新建房间"，说明"填写宽 / 深 / 高作为布局输入，不承诺测量精度"，按钮"取消"/"创建空白房间"/"用卧室模板"；两者均需填名称，创建后写入默认尺寸（4×4×2.8 m）与自动户型占位；模板方式预置卧室 3 件家具并标 `templateKey=bedroom`。

### 6.4 三维房间（room3d）

> 交互基准：《三维空间视图与模型管理交互设计规范 V1.0》/ `document/三维视图交互逻辑规范_V1.0.md` / 《物品添加与管理业务规则 V1.0》§3.2。原「三模式 + 自由旋转视角 + 短按直接建档 + 常驻模型库 + 页面下方信息卡」口径已废止。

- **模式栏**：无。单一主视图，固定等距轴测视角（不提供自由旋转/平移）。
- **字段与信息**：
  - a) 房间画布：按家具 `position` 与 `size` 摆放家具块；
  - b) 点击家具后从三维窗口下沿展开底部抽屉（cover-view）：家具名称与有效物品总数、收纳节点 chip（含各节点有效物品数）、当前节点直接关联物品（最多 5 件）；操作「＋添加物品 / 查看全部 / 关联已有 / 更多」，标题栏可收起、✕ 关闭；
  - c) 家具模型库：点「＋ 家具」才展开的抽屉，11 类可点击添加；
  - d) 从已有物品选择面板：列出未结束档案及当前位置，点选即绑定/改存放位置；
  - e) 列表降级视图：标题"家具列表（三维降级）"，逐项显示家具名与"N 件关联物品"，点击进入家具详情。
- **交互**：
  - a) 工具条切换画布/列表视图，「复位视图」恢复默认比例；
  - b) 家具短按（点击）→ 选中并打开底部抽屉（不跳页）；短按空白取消选中并关闭抽屉；点抽屉节点切换当前节点物品；
  - c) 家具拖动 → 位置按房间边界钳制并保存，提示"位置已保存"；拖空白不改变视角与家具；
  - d) 家具长按 → 删除二次确认；若有关联物品或子节点则阻断，提示先迁移存放位置，物品记录不丢；
  - e) 旋转通过视图内 ↶ / ↷ 按钮完成，每次 ±90° 并对 [0, 2π) 取模；双指仅有限缩放视图（不改变等距角度与家具尺寸）；
  - f) 添加物品两路径：从已有物品中选择（写入当前节点存放关系）/ 新建物品建档（预选当前家具节点）；
  - g) 从模型库添加家具：同名按类别计数递增命名，自动建立对应"家具"节点，提示"已添加，可拖动摆放"；无房间时提示"请先创建房间"。
- **提示文案**：画布"点家具查看与添加物品 · 拖动摆放 · 双指缩放视图 · 按钮旋转 90° · 长按删除"；空房间"房间还是空的，点下方「＋ 家具」添加第一件家具"。

### 6.5 家具详情（furniture）

- **字段**：图标、名称、"分类 · 模型：X"；收纳节点树（根节点标"家具"，子节点标类型）；关联物品列表（名称+路径）。
- **交互**：
  - a) "更换外观模型"在"默认"/"木色原木"间切换，提示"外观已更换，节点与物品关联不变"；
  - b) "删除家具"：有关联物品或子节点时阻断（同上文案），否则删除家具及其全部节点并返回三维；
  - c) "＋ 新增"建收纳节点（根下新增类型"收纳盒"，节点下新增类型"抽屉/隔层"）；
  - d) 点击节点进入收纳节点页；点击关联物品进入物品详情。
- **提示**：模型外观与逻辑收纳节点解耦：更换模型不会破坏节点与物品关联；无节点显示"暂无节点"；无关联物品显示"还没有物品绑定到这里"。

### 6.6 收纳节点（node）

- **字段**：面包屑完整路径、节点名、类型标签、"用户确认事实"标签；下级位置列表；节点内物品列表（名称+跟踪模式）。
- **交互**：
  - a) "重命名"弹层（标题"重命名节点"，显示原名，按钮"取消"/"保存"）；
  - b) "删除节点"：含下级节点或物品时阻断，提示"含 N 个下级节点 / N 件物品，禁止删除"，否则删除并返回家具详情；
  - c) 底部"在此位置添加物品"进入物品建档并预选本节点。
- **提示**：允许同名，用完整路径与排序区分；删除含下级节点或关联物品的节点会被阻断，须先迁移或归档；无下级显示"无下级位置"，无物品显示"该节点暂无物品"。

### 6.7 物品（itemList）

- **字段**：搜索框（占位"搜索物品名称 / 分类"，右侧显示结果数）、筛选标签"全部/位置未知/低库存"、物品卡（名称、位置文本、低库存或跟踪模式标签）、右下"＋"悬浮按钮。
- **交互**：输入即时按名称/分类过滤；筛选"位置未知"仅显示 `unknown`；筛选"低库存"仅显示余额≤阈值且阈值>0 的物品；点击卡片进入物品详情；悬浮按钮进入物品建档。
- **提示**：无结果显示"没有匹配的物品"；列表默认排除 `ended` 物品。

### 6.8 物品建档（itemEdit）

- **字段**：名称（必填，标"*必填"）、分类（下拉，含"未分类"）、跟踪模式（下拉三选）、当前位置（下拉，选项为"位置未知 / 暂不指定"与各节点完整路径）、备注；新建且跟踪模式为"只记库存/位置+库存"且尚无库存记录时，显示"初始库存"卡（初始数量、单位、最低库存阈值）。
- **交互**：
  - a) 底部"建档"（编辑时为"保存"）保存并进入物品详情（带"档案已建立"引导）；
  - b) "保存并继续"保存后清空表单停留在建档页，支持连续建档；
  - c) 切换跟踪模式时动态展开/收起初始库存卡；
  - d) 名称为空时输入框标红并提示"名称为必填项"。
- **提示**：新建说明"只需名称即可保存；分类、照片、位置可后续补充（渐进式建档）"；编辑说明"仅名称即可建档，其余信息随时补充"；"创建时填写的位置属于初始存放信息，不会记为一次「移动」"；初始库存"属于建档时的初始状态，不生成交易流水；后续变更请走库存交易"，已建档则提示"初始数量已在建档时设定；后续变更请走库存交易的入库 / 消耗 / 调整"。

### 6.9 物品详情（itemDetail）

- **字段**：
  - a) 建档引导卡（刚建档时）："档案已建立 / 下一步：<提示>" + 操作按钮；
  - b) 概览：名称、分类·跟踪模式、"档案 N%"与进度条；
  - c) 状态卡：状态标签（"已定位"/位置状态）、位置完整路径、最近更新时间、四状态标签；
  - d) 库存卡（有库存记录时）：余额、单位、阈值、"低于阈值/正常"标签、"查看交易流水"；
  - e) 操作区：编辑档案、移动物品、记一笔库存（有库存记录时）、位置历史、结束管理。
- **引导逻辑**：无位置或位置未知 → "补充位置，初始存放信息不记为一次移动"，按钮"去定位"；有库存且余额为 0 → "记录初始库存，后续变更走库存交易"，按钮"去入库"；其余 → "继续完善分类、备注等信息"，按钮"去完善"。
- **交互**：各操作进入对应页面；"结束管理"若有库存余额>0 则阻断，提示"剩余 N 单位库存，须先明确处置方式"；成功则标记 `ended` 并写入 `end` 类型历史；底部"返回物品列表"直接进入物品列表。
- **提示**：未知/外出状态不显示具体节点；档案完整度按名称、分类、备注、照片、位置五项中已填项占比计算，仅提示不强制。

### 6.10 移动物品（move）

- **字段**：当前信息卡（物品名、当前位置、目标位置）、目标状态标签（在家/位置未知/外出携带/借出）、目标位置树（空间→房间→根节点及子节点的收纳节点）、备注输入框。
- **交互**：
  - a) 选择目标状态；选择"在家"以外的状态时清空所选节点；
  - b) 选择节点（根节点或子节点）时自动将状态置为"在家"并回显完整路径，选中项高亮；
  - c) "确认移动"：若状态为"在家"但未选节点，提示"选择「在家」需同时选定具体位置"；否则写入当前位置与一条历史，提示"已确认：<移动类型>，历史 +1"并返回详情。
- **提示**：选择"在家"需同时选定具体位置；未知首次确认到具体位置记为独立事件。

### 6.11 位置历史（history）

- **字段**：标题"物品名 · 位置历史（N）"（我的入口为"位置历史（N）"）；时间轴逐条显示移动类型标签、"来源 → 目标"路径或状态、时间与备注。
- **提示**：无历史显示"暂无历史"；当前位置与历史在同一事务内更新；首次位置确认不伪装为 A→B 移动；历史只读。

### 6.12 库存总览（inventory）

- **字段**：库存卡（物品名、"阈值 N 单位 · 分类"、余额，低库存时余额标警示色），按"（余额 − 阈值）"升序排列，低库存置顶。
- **交互**：点击卡片进入库存详情；底部"查看提醒中心"。
- **提示**：暂无库存物品显示"暂无库存物品"；库存不得低于零；纠错走"调整"交易，与真实消耗分开记录。

### 6.13 库存详情（inventoryDetail）

- **字段**：余额卡（余额大字、单位、阈值、进度条；低于阈值时显示"达到最低库存，已生成提醒"）；库存变更（数量、说明 + 入库/消耗/调整三个按钮）；交易流水（类型+增减量、时间·说明、变更后余额）。
- **交互**：
  - a) 数量非正数提示"数量必须为正数"；
  - b) 消耗超过余额时拒绝，提示"库存不足：当前仅 N 单位；纠错请走「调整」"；
  - c) 入库/消耗按增减更新余额；"调整"直接把余额设为输入数量；
  - d) 每次成功生成一条交易并刷新提醒，提示"<类型>成功，余额 N"。
- **提示**：无交易显示"暂无交易"；未启用库存跟踪的物品进入本页显示"该物品未启用库存跟踪"。

### 6.14 提醒中心（alerts）

- **字段**：提醒卡（物品名、"当前 N 单位 · 阈值 X"、待处理/已忽略状态）。
- **交互**："去处理"进入库存详情；"忽略"将状态置为 `ignored`（不改变库存事实）。
- **提示**：无待处理提醒显示"✅ 暂无待处理提醒"；补货使余额高于阈值后，当前提醒周期自动结束并恢复（`recovered`）。

### 6.15 我的（profile）

- **字段**：账户卡"康女士 / 个人单用户 · 本地演示模式"，标签"本地可用""待同步标记由真实后端处理"。
- **入口**：空间与房间、全部位置历史、提醒中心、重置演示数据。
- **提示**：本页数据全部为模拟数据；真实版本的数据隔离、照片私有存储与备份恢复由后端实现，本演示不涉及。

## 七、交互逻辑与业务规则

### 7.1 导航与反馈

- a) 页面切换维护返回栈，支持界面内返回与浏览器前进/后退；栈空时提示"已经在首页"。
- b) 需命名的操作统一用底部确认层（标题 + 说明 + 名称输入 + 按钮），名称为空就近提示。
- c) 所有写操作以 Toast 反馈结果；成功用_ok_样式、失败用_err_样式，约 1.9 秒后淡出。
- d) 每次写操作同步写入操作日志并实时重绘数据快照。

### 7.2 核心业务规则（以界面行为为准）

| 规则 | 界面行为 |
| --- | --- |
| 单物件单位置 | 移动只更新一个 `currentNodeId`；绑定沿 `nodes.furnitureId` + `items.currentNodeId` 单源表达，不双写 |
| 位置与历史同事务 | 移动成功同时更新当前位置并新增一条 `movements`，类型由前后状态判定 |
| 首次位置确认独立成类 | 原为"位置未知/无节点"且首次确认到具体"在家"位置 → 类型 `first_confirm`，不伪装为 `move` |
| 外出/归还单列 | 在家→外出/借出记 `out`；外出/借出→在家记 `return` |
| 在家须选节点 | 目标状态为"在家"但未选收纳节点时拒绝确认 |
| 初始信息不记移动 | 建档时填写的位置属初始存放信息，不生成历史；初始库存不生成交易流水 |
| 库存不为负 | 消耗使余额<0 时拒绝并保留原值；纠错走"调整"，与消耗分开记录 |
| 关联保护 | 删除含物品/子节点的对象一律阻断，提示先迁移或归档 |
| 换模型解耦 | 更换外观模型不影响收纳节点与物品关联 |
| 阈值提醒 | 余额≤阈值且阈值>0 生成 `pending` 提醒；同物品仅保留一条未恢复提醒；补货高于阈值后置 `recovered` |
| 结束管理 | 有剩余库存余额时阻断；无余额则标 `ended` 并写 `end` 类型历史 |
| 布局合法性 | 户型越界或重叠不写入状态；家具变换按房间边界与尺寸上下限钳制 |
| 档案完整度 | 名称/分类/备注/照片/位置五项按已填比例计算，仅作提示 |

## 八、异常与降级口径

四条口径（演示折叠面板明示，可手动验证）与界面内具体表现：

| 口径 | 界面触发与提示 |
| --- | --- |
| 库存消耗导致余额为负 → 拒绝，纠错走"调整" | 库存详情消耗超额提示"库存不足：当前仅 N 单位；纠错请走「调整」" |
| 删除含物品的节点/家具 → 阻断并提示先迁移或归档 | 家具删除提示"已被关联：N 件物品 / N 个节点，须先迁移或归档"；节点删除提示"含 N 个下级节点 / N 件物品，禁止删除" |
| 三维不可用 → 切"列表"视图，物品管理仍可完成 | 三维房间右上角切换"家具列表（三维降级）"，家具与位置管理仍可操作 |
| 位置未知首次确认到具体位置 → 记为独立事件，不伪装为移动 | 移动类型 `first_confirm`，历史标签"首次位置确认" |

补充（界面内可见的约束提示）：户型越界/重叠"布局与其他房间重叠或越界，未保存"；结束管理有余额"剩余 N 单位库存，须先明确处置方式"。

## 九、术语表（统一口径）

| 术语 | 含义（以界面为准） |
| --- | --- |
| 空间 | 最高管理层级，其下可建多个房间；首版仅个人单用户 |
| 房间 | 空间的下一层，含宽/深/高与户型位置，可空白或用场景模板 |
| 户型总览 | 首页按房间 `floor` 渲染的平面示意，可编辑布局；墙线为示意，不承诺测量精度 |
| 三维房间 | 房间画布页，单一主视图 + 固定等距视角 + 列表降级视图 |
| 家具 | 既是外观模型，也是逻辑位置根节点；外观与逻辑节点解耦 |
| 收纳节点 | 家具下的多级位置（家具→抽屉/隔层→收纳盒），构成物品存放路径 |
| 物品 | 档案主体，仅名称即可建档，跟踪模式决定记位置/库存/两者 |
| 当前位置 | 用户确认事实，由 `locationStatus` + `currentNodeId` 表达 |
| 移动 | 用户显式确认的位置变更，与历史同事务写入，按前后状态分类 |
| 库存 | 物品的可选跟踪维度，含余额、单位、阈值；余额不得为负 |
| 交易 | 库存变更流水，分入库/消耗/调整；初始库存不生成交易 |
| 提醒 | 余额≤阈值时生成，可忽略或处理，补货后自动恢复 |
| 关联保护 | 删除含物品或子节点的对象前阻断，须先迁移或归档 |
| 占位模型 | 无合适模型时的默认模型，不依赖照片 |
